# 代码工程结构与模块架构

## 1. 依赖方向与分层原则

系统模块严格按层次组织，依赖只能**自顶向下单向依赖**，禁止反向依赖与跨层泄漏：

```
        api                       HTTP 接入：路由、DTO、接入闸门、错误映射
         │
      runtime                     任务编排：任务注册表、生命周期管理、续跑门面
         │
 ┌───────┼────────┬───────────┬────────────┐
 ▼       ▼        ▼           ▼            ▼
subagents  context  llm      tools        guardrails
 │         │         │         │              │
 └─────────┴─────────┴────┬────┴──────────────┘
                          ▼
                        core                    纯契约：消息模型、状态类型、错误定义、工具协议
```

### 核心依赖规则

1. **`core` 零业务依赖**：只含不可变数据模型（`AgentState`, `Message`, `ToolCall`）与纯函数（`apply_update`, `check_invariants`），不做任何 I/O 操作，不依赖系统内其他层。
2. **API 只依赖 `runtime` 门面**：HTTP 层与 SSE 事件通道不直接接触网关、工具实现或存储细节。
3. **工具层不依赖运行时**：只依赖 `agent_runtime.core`（工具协议、异常）与 `agent_runtime.guardrails`（安全校验纯函数）。
4. **Sidecar 服务完全独立**：`services/*`（如 `bash_shell`、`web_search`）作为独立子进程运行，与 Agent 运行时无代码级依赖，仅通过回环 HTTP 通信。
5. **子智能体依赖网关、工具与护栏**：不反向依赖主循环。主循环仅通过工具注册表将其作为普通工具调用。
6. **护栏为纯函数集合**：三级权限判定、重复指纹拦截、连续错误计数、金丝雀泄露扫描均为无副作用的确定性函数，可离线全量单测。
7. **可观测性为横切旁路**：各层可向事件总线、日志或追踪接口发送数据，但观测层自身不反向依赖任何业务逻辑。
8. **配置为全局共用底座**：`baseagent_config` 独立成顶层包，负责配置加载、强类型验证与环境变量映射，所有层与独立 Sidecar 均可直接引用。

系统通过 `import-linter` 静态分析工具在测试阶段强制执行上述分层规则，任何跨层反向依赖均会阻断流水线。

```

│   ├── checkpoint/           状态持久化：CheckpointStore、原子提交、崩溃恢复扫描
│   ├── approval/             人工审批：确定性 approval_id 计算、决策绑定、审批白名单
```

## 3. 核心子系统架构与协作契约

### 3.1 运行时内核（`agent_runtime/loop`）
主循环采用去阶段化的纯 Agent 循环模式：
1. **调用模型**：根据当前 `AgentState` 装配上下文并请求 LLM。
2. **提交与广播**：收到模型回复后立即提交检查点，随后广播事件流。无工具调用则直接结束任务。
3. **执行工具**：将待执行工具批次交给工具包装层处理；如遇越级操作抛出 `ApprovalRequired`，立即记录并安全挂起。
4. **状态追加与提交**：工具结果转换并追加进 `AgentState`，执行第二次检查点原子提交，更新循环计数，进入下一轮。

### 3.2 检查点与可恢复性（`agent_runtime/checkpoint`）
- 每一个回合在模型回复后与工具执行后各提交一次原子快照。
- 任务挂起或意外中断后，系统通过 `scan_for_recovery` 识别未完成状态，通过确定性的 `resume` 流程从最近的检查点无缝拉起，杜绝中间状态悬空。

### 3.3 确定性人工审批（`agent_runtime/approval`）
- 权限判定 `check_permission` 为无 I/O 的纯函数，依据明确的白名单与命令正则划定 `read_only` / `workspace_write` / `full_permissions`。
- 越级操作抛出异常并落盘挂起，生成的 `approval_id` 由任务与调用特征确定性计算，保证进程重启后前端审批卡片依然合法绑定。

### 3.4 上下文与缓存优化（`agent_runtime/context`）
- **前缀稳定性**：提示词系统层与冻结资产置于消息最前端，保证大模型供应商的 Prompt Cache 命中率。
- **动态能力延迟挂载**：高频工具直接暴露 Schema（`pinned`），庞大的外部 MCP 工具采用两阶段按需激活（`deferred`），通过索引检索 + `mcp_describe` 调用，彻底杜绝上下文膨胀与前缀抖动。
- **双层观察值治理**：Shell 层流式截取与后处理层 Token 阈值裁剪配合，超长输出生成结构化轮廓并离线落盘至 `artifact://`。

### 3.5 模型网关（`agent_runtime/llm`）
- 统一管理 Reasoning 档与 Fast 档模型端点，内置自适应并发控制、指数退避重试与自动降级熔断。
- 针对不同模型厂商的思考模型（Thinking / Reasoning Content），支持细粒度的回传策略与通道控制。

## 4. 架构约束与质量保障

| 维度 | 约束标准 | 自动化保障方式 |
|---|---|---|
| **代码依赖** | 严格单向分层，核心层零依赖 | `import-linter` 规则集在 CI 中自动化检查 |
| **状态不可变** | 状态更新必须通过 `apply_update` 产生新实例 | 不可变 dataclass 设计 + 不变量检查 `check_invariants` |
| **安全隔离** | 命令执行与外网爬取必须处于独立子进程 | Sidecar 架构 + 回环地址绑定 + 白名单环境变量 |
| **测试完整性** | 关键逻辑覆盖边界与变异场景 | 自动化回归测试套件 + 属性测试（Hypothesis） |
| **回放一致性** | 真实轨迹可重放，事件序列严格单调递增 | 事件中心全局递增序列号 + JSONL 轨迹全量落盘 |
