# 0006 主循环收敛为纯 agent loop，取消预算

- 状态：**已采纳并实施**（后端与前端都已落地，旧的 `plan` / `node.finished` 事件已删除，见 [事件契约 §4](../09_api/02_events_contract.md)）
- 取代：[0001 主循环保留五阶段](0001-main-loop-shape.md)
- 影响：[02_runtime](../02_runtime/)、[03_context/05_inheritance.md](../03_context/05_inheritance.md)、[06_subagents](../06_subagents/)、[07_llm_gateway](../07_llm_gateway/)

## 背景

0001 选了 planner / budget_guard / executor / tool_runner / evaluator 五阶段加路由表。这是**工作流**，不是 agent loop：下一步由 `phase` 和路由函数决定，planner 与 evaluator 是代码替模型做的决策，重规划、打回上限、预算守卫都是为这套结构打的补丁。BaseAgent 要做的是通用 Agent 底座，控制权应当在模型手里，代码只管护栏与落盘。

## 决定

1. **主循环只有一个动作**：调模型；有工具调用就执行并把结果追加进 transcript，再调模型；没有工具调用即结束。
2. **循环只依赖四样东西**：工具集（内置、MCP、技能）、上下文装配器、会话草稿、模型句柄。
3. **没有预算。** 不设 Token、步数、挂钟上限，不设预算守卫与子智能体账本。额度耗尽表现为模型接口报错，与其他模型错误同一路径：异常传出，任务停止，检查点保留，可续跑。
4. **planner 取消**：计划是工具 `update_plan`，写会话草稿，模型想用才用。
5. **evaluator 取消**：没有验收阶段，也没有"打回"。代码得出的证据（`verification`）以提醒的形式随每次上下文装配注入，由模型自己决定是否继续。
6. **其余能力移出循环**，挂在固定接缝上：

   | 能力 | 位置 |
   |---|---|
   | 权限、审批、重复指纹、连续错误 | 工具包装层 |
   | 不可信内容信封、观察值裁剪、产物落盘 | 工具后处理 |
   | 折叠、压缩、技能索引、草稿回显、证据提醒 | 上下文装配器 |
   | 计量、降级端点、金丝雀检测 | 模型网关 |
   | 检查点、事件、轨迹 | Recorder（循环边界的订阅者） |
   | 取消、任务生命周期、部分交付 | Supervisor（循环外层） |

7. **继承规则**：哪些内容跟随对话向后传递、哪些不传，见 [上下文继承](../03_context/05_inheritance.md)。

## 放弃了什么

- **强制验收。** 模型可能过早宣布完成。缓解只有证据提醒，不再有关卡。
- **定期重规划、连续失败回规划。** 模型看得到工具错误，自己调整。
- **里程碑的路由语义。** 计划只是草稿里的一个字段，不影响控制流。
- **预算类刹车。** 失控任务只剩四道刹车：用户取消、工具包装层的重复拦截与连续拦截上限、金丝雀泄露终止、余额耗尽。这是有意接受的风险。

## 后果

- 状态模型去掉 `phase`、里程碑、步数与 Token 计数、终止标志、重规划与打回计数等控制字段，新增 `plan`、`facts`、`failed_attempts`，`schema_version` 升到 3。会话继承来的记忆不再放进状态，只在任务启动时冻结进提示词资产，因此"任务内覆盖继承摘要"这类问题结构上不存在。
- 提交点由"阶段边界"改为"回合"，一个回合有两次提交：模型回复带工具调用时先提交，工具结果追加后再提交。取代 `dispatch_started`：尾部存在未配对的调用，即表示"可能已部分执行"。
- 审批仍是落盘挂起（[0002](0002-approval-suspension.md) 不变），只是挂起点由 `tool_runner` 阶段变成工具执行步骤。
- 子智能体就是工具里嵌套的一次 `run`，不再有独立额度。
- 终态里不再有"预算耗尽"，`terminated` 只剩安全终止。
- 测试中绑定阶段与路由的部分作废并重写；真实模型评测的 7 个基线用例保留作回归对照。

## 迁移

| 现有 | 去向 |
|---|---|
| `loop/routes.py`、`loop/drive.py`、`loop/stages/*` | 删除，换成循环内核与回合提交 |
| `loop/stages/planner.py`、`evaluator.py`、`contracts.py` | 删除；`update_plan`、`note` 作为内置工具 |
| `loop/stages/budget_guard.py`、`guardrails/budget.py`、`guardrails/ledger.py` | 删除 |
| `loop/stages/tool_runner.py` | 拆为工具包装层（权限、审批、指纹）与工具后处理（信封、裁剪、产物） |
| `loop/stages/executor.py` | 并入循环内核；金丝雀检测移到网关 |
| `checkpoint/recovery.py` | 简化为"补齐尾部未配对调用" |
| 配置 `[runtime.guardrails]` 预算项、`[runtime.loop]` 重规划与打回项 | 删除 |

迁移完成前，各设计文档描述的是目标行为；与代码不一致处以本决策为准，代码按本表迁移。
