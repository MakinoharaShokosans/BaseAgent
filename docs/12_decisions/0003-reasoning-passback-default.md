# 0003 思考内容默认不回传，按端点显式开启

- 状态：**已采纳**
- 影响：[07_llm_gateway/03_reasoning_content.md](../07_llm_gateway/03_reasoning_content.md)、[02_runtime/01_state_model.md](../02_runtime/01_state_model.md)

## 背景

推理模型会返回思考内容。有的服务商要求在工具调用往返中原样回传，有的明确不接受回传，有的根本不返回。代码需要决定：取不取、存不存、回不回传。

## 选项

**A. 默认不回传，端点上显式声明才开启。**
- 对不返回、不需要回传的模型零影响。
- 错误回传的风险（被拒绝、多算 Token）被默认值挡住。
- 代价：换成要求回传的模型时，需要在配置里显式开启，忘了配置会出现质量下降或报错。

**B. 默认回传。**
- 对要求回传的模型开箱即用。
- 对不接受回传的模型，一上线就失败，且原因不明显。

**C. 按已知服务商的名字或域名自动判断。**
- 用户无需配置。
- 服务商接口会变，规则会过时；兼容服务大量存在，域名不能代表行为。

## 决定

选 A。取与存始终执行（成本低，且对审计有价值），只有**回传**是显式开关，默认 `never`。同时要求每个启用的端点附一条"多轮工具调用加思考"的集成测试，作为配置验证。

## 后果

- `Message` 增加 `reasoning`、`reasoning_state`、`produced_by`。
- 端点配置增加 `reasoning_field` 与 `reasoning_passback`。
- 降级到另一个端点时，来自原端点的不透明载荷不会被发送。
- 文档里需要维护一份"已验证端点清单"，记录哪些端点验证过哪种回传策略。
- **补充（接入 DeepSeek 后）**：有的服务商在思考模式下要求"带工具必须回传全部历史思考"。本决定的"默认不回传"不变，但需要两个配套控制：`thinking_control` / `thinking_with_tools`（带工具的请求关闭思考），以及预留的回传策略 `all_when_tools`。首版选择"带工具不开思考"，见 [DeepSeek §4](../07_llm_gateway/04_deepseek.md)。
- 思考内容不进入记忆、交付与其他模型的上下文，金丝雀检测覆盖它。
