# 0004 追踪采用内部 span 模型加可插拔导出，避免侵入式第三方框架绑定

- 状态：**已采纳**
- 关联模块：[08_observability/03_tracing.md](../08_observability/03_tracing.md)、`pyproject.toml`

## 背景

在 Agent 执行跟踪与可观测性体系选型中，需要支持全流程调用树追踪（网关调用、工具派发、审批等待、子智能体执行）。若直接绑定特定观测厂商的侵入式回调或重量级 SDK，会导致核心运行时与外部依赖强耦合，破坏运行时的自包含性与确定性离线能力。

## 选项

**A. 自有轻量 span 模型，本地 JSONL 为主，导出器可插拔（OTLP、Langfuse 可选）。**
- 核心不依赖任何第三方追踪库，开箱即用。
- 本地落盘 JSONL，满足离线审计与无网络环境要求。
- 同一棵调用树可通过轻量导出器输出到多个标准后端。

**B. 直接采用 OpenTelemetry SDK 作为内部核心实现。**
- 生态和语义约定现成。
- 核心默认依赖变重，SDK 的异步上下文与自研事件循环模型需要深度适配。

**C. 针对单一厂商 SDK 在网关与工具派发处手动打点。**
- 实现快，但与单个厂商平台强绑定，灵活性差。

## 决定

选 A。内部 span 模型结构极简、与事件和轨迹的关联键（`task_id`、`step_id`、`span_id`）天然一致；导出器接口正交解耦，通过标准 OTLP 导出器即可覆盖包括 Langfuse、Jaeger 等在内的多数观测后端。

## 后果

- 轨迹、事件信封、日志上下文统一包含 `span_id` 与 `parent_span_id`。
- 第三方观测库移出核心依赖，作为可选插件提供。
- 远程导出与敏感内容导出默认关闭，开启需显式配置并在界面予以提示。
- 挂起等待审批的时间在追踪里归为独立的 `guard:approval` span。
