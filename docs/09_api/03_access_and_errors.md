# 接入控制与错误模型

## 1. 威胁模型

这个 API 背后有**命令执行、文件读写、联网检索**的能力，调用它等于以运行用户的身份操作这台机器。所以接入层的底线是：**只有用户本人的浏览器能用，别的东西都不行**。

部署假设：单用户、本机、回环。需要防的是：

| 攻击 | 例子 |
|---|---|
| 恶意网页的跨站请求 | 用户访问了某个网站，页面里的脚本向 `http://127.0.0.1:8000` 发 POST，提交任务 |
| DNS 重绑定 | 恶意域名先解析到公网、再解析到 `127.0.0.1`，让浏览器认为这是同源 |
| 本机其他进程 | 同一台机器上的另一个用户或进程，直接调用接口 |
| 误暴露 | 配置改成监听 `0.0.0.0`，整个局域网都能调用 |

## 2. 现状的三道防线与缺口

| 防线 | 实现 | 防什么 |
|---|---|---|
| 绑定回环 | 配置校验，服务只允许监听 `127.0.0.1`、`localhost`、`::1`，改成别的会直接拒绝启动 | 误暴露 |
| Host 校验 | 请求头 `Host` 的主机名必须在允许集合内（回环名始终允许，另可配置） | DNS 重绑定 |
| Origin 校验 | 写操作（POST、PUT、PATCH、DELETE）若带 `Origin`，必须在 CORS 白名单内 | 跨站请求 |

此外 CORS 默认拒绝，只放行白名单（前端开发服务器），`allow_credentials=False`。中间件是**纯 ASGI**，不碰请求体，对 SSE 透明。豁免路径只有 `/`、`/health`、`/api/v1/health`、文档页。

### 2.1 缺口

1. **没有令牌认证。** 令牌相关的函数是占位实现（`provision_api_token` 直接返回 `None`，中间件的 `require_token`、`token` 参数被接收后未使用）。根路径的响应还引用了 `cfg.server.auth_enabled` 之类的配置并声称"令牌见某文件"，与实际不符，容易让人误以为已有保护。**任何本机进程都可以不带任何凭据地提交任务、读写文件。**
2. **Origin 校验只在请求带 `Origin` 时生效。** 浏览器的跨站 POST 一定带，所以浏览器场景是安全的；但非浏览器客户端（curl、脚本）不带，直接通过。这与缺口 1 同源：它们本来就不受任何认证约束。
3. **读请求不做 Origin 校验。** GET 都放行。恶意网页无法读取跨域响应（CORS 挡），但可以触发有副作用的 GET——目前所有 GET 都是只读，这一点需要在评审时持续保持，不得新增有副作用的 GET。
4. **Host 校验后接受的名字取决于配置**，加入反向代理的自定义域名时，要同步评估重绑定风险。

## 3. 新版：本地令牌认证

目标：让"同一台机器上的其他进程"也过不了。

### 3.1 令牌的生成与存放

- 首次启动生成 256 位随机令牌，写入 `storage/api_token`，权限 0600，目录 0700。`.gitignore` 已包含该路径。
- 令牌**不写日志，不进事件，不出现在启动看板里**（只显示文件路径）。
- 轮换：删除文件并重启即可；提供 `aegis token rotate` 命令。
- 启动器 `aegis` 起前端时，把令牌通过安全的方式交给前端（环境变量注入到开发服务器的代理层，见 §3.3），不要写进前端的静态文件。

### 3.2 校验

- 请求头 `Authorization: Bearer <token>`。比较使用常量时间比较。
- 豁免路径不变：`/`、`/health`、`/api/v1/health`、文档页（文档页在生产模式下也建议关闭）。
- 失败返回 401，错误体同构，**不区分"缺少"和"错误"**，也不回显令牌。
- 失败次数限速：同一来源连续失败达到阈值后短暂拒绝，避免暴力猜测。令牌熵足够高时意义有限，但成本低。

### 3.3 浏览器与 SSE 的问题

`EventSource` 无法设置自定义请求头。三种做法，按优先级：

| 做法 | 说明 | 取舍 |
|---|---|---|
| **A. 前端经同源代理访问 API**，代理在服务端侧加上 `Authorization` 头 | 开发服务器（Vite）配置代理，浏览器只和前端同源通信，令牌留在代理侧，不进入浏览器 JS | **首选**。令牌从不暴露给页面脚本 |
| B. 用 `fetch` 流式读取 SSE，自己设置请求头并实现重连 | 令牌在浏览器内存中 | 可行。前端已经使用 `@microsoft/fetch-event-source`，它支持自定义请求头并实现了重连与 `Last-Event-ID`，所以这条路几乎零成本；代价是令牌会进入页面脚本可访问的范围 |
| C. 令牌放在查询参数 `?token=` | 实现最简单 | **不推荐**：令牌会进入访问日志、浏览器历史、`Referer`。仅限回环环境的最后手段，且服务端不得记录查询串 |

### 3.4 与 Host、Origin 的关系

三者叠加，各管一类：令牌挡"没有凭据的调用者"，Host 挡重绑定，Origin 挡跨站。令牌存在后，Origin 校验仍然保留（令牌若被前端代理自动携带，恶意网页向代理同源地址发请求的风险需要由 Origin 校验兜住）。

## 4. 文件系统相关端点的风险

| 端点 | 风险 |
|---|---|
| `GET /system/fs/directories?path=` | **可浏览主机上的任意目录**，包括 `/`。返回目录名和是否有子目录。没有认证时，本机任何进程可借此枚举文件系统结构 |
| `POST /system/fs/pick-directory` | 在宿主机上弹出原生目录选择窗口（Zenity、KDialog、Tkinter），**阻塞线程最长 180 秒**。可被反复调用造成桌面骚扰，也占用线程池 |
| `POST /workspaces` | `root_path` 不校验，可设为 `/` 或系统目录，使文件接口和工具沙箱的"工作区内"约束失去意义 |
| `PUT /workspaces/{id}/files/content` | 写文件无大小上限、非原子 |

处理：

1. 全部纳入令牌认证。
2. 目录浏览：限制在用户主目录之下以及显式配置的根；隐藏文件与常见系统目录不返回；对返回条数设上限。如果必须允许浏览整个磁盘，要作为显式的配置开关，默认关闭。
3. 原生选择窗口：同一时刻只允许一个；超时缩短；调用频率限制。
4. 工作区路径校验，规则见 [01 §1](01_endpoints.md)。
5. 文件写入：大小上限、原子写入、`base_hash` 冲突检测。

## 5. 其他输入防护

| 项 | 要求 |
|---|---|
| 请求体大小 | 全局上限 2 MB，超出 413；文件保存接口单独放宽到与工具一致 |
| 字符串长度 | `task_goal`、`name`、`description` 等有上限，超出 400 |
| 路径参数 | `task_id`、`session_id`、`artifact_id` 只接受安全字符集，防止路径穿越到轨迹与产物目录 |
| 速率限制 | 提交任务本身受 `max_concurrent_tasks` 限制；对高频读接口做简单的令牌桶，防止被刷 |
| 反序列化 | 只接受 JSON；Pydantic 严格校验，未知字段按接口约定忽略或拒绝（写请求拒绝） |

## 6. 错误模型

所有错误同一个信封：

```json
{
  "error": {
    "code": "TASK_NOT_FOUND",
    "message": "任务不存在",
    "details": { "task_id": "…" },
    "trace_id": "…"
  }
}
```

响应头带 `X-Trace-ID`，与错误体里的相同。客户端可以在报告问题时附上它，服务端日志、轨迹用同一个 `trace_id` 关联。

### 6.1 状态码映射

领域异常在 `api/errors.py` 的一张表里映射，沿 MRO 自下而上查找：

| 状态码 | 场景 | 示例 `code` |
|---|---|---|
| 400 | 请求体校验失败 | `VALIDATION_ERROR`（详情最多返回 10 条） |
| 401 | 认证失败（新增） | `UNAUTHORIZED` |
| 403 | Host 或 Origin 不被允许 | `HOST_NOT_ALLOWED`、`ORIGIN_NOT_ALLOWED` |
| 404 | 资源不存在 | `WORKSPACE_NOT_FOUND`、`SESSION_NOT_FOUND`、`TASK_NOT_FOUND`、`ARTIFACT_NOT_FOUND` |
| 409 | 状态冲突 | 任务状态不允许该操作、审批 ID 不匹配、工作区路径冲突、文件哈希冲突 |
| 413 | 请求体过大（新增） | `PAYLOAD_TOO_LARGE` |
| 422 | 路径越界、工作区非法 | `PATH_ESCAPE_DETECTED` |
| 429 | 并发任务已满 | `TASK_QUEUE_FULL` |
| 500 | 内部错误；细节只进日志，不外泄 | `INTERNAL_ERROR` |
| 503 | 下游不可用 | `DEPENDENCY_UNAVAILABLE`、`LLM_UNAVAILABLE` |

400 与 422 的区分：400 是请求**格式**不对（缺字段、类型错），422 是格式正确但**语义**被拒（路径越界）。

### 6.2 规则

1. **领域层不感知 HTTP。** 领域异常带稳定的 `code`、`message` 和 `context`，映射集中在一处。
2. **`code` 稳定、`message` 面向人。** 客户端按 `code` 分支，不按 `message` 文本匹配。
3. **500 不泄漏内部细节。** 堆栈、路径、SQL 只写日志，响应里只有 `INTERNAL_ERROR` 与 `trace_id`。
4. **中间件与路由用同一套响应形状。** 纯 ASGI 的安全闸门直接构造同构响应，不另起一套格式。
5. **`details` 不含敏感信息**：不回显令牌、密钥、完整请求体。
6. **同一语义，同一 `code`。** 例如"任务不在可操作状态"在审批、续跑、取消里使用同一个错误。

## 7. 不变量

1. 服务只监听回环地址，配置改动不能绕过。
2. 没有有效令牌的请求，除豁免路径外一律 401。
3. 令牌不出现在日志、事件、错误体、启动看板中。
4. 所有 GET 无副作用。
5. 文件系统浏览有明确边界。
6. 500 不外泄内部细节。
7. 每个错误响应都带 `trace_id`。

## 8. 测试要点

- 闸门：Host 不合法、Origin 不合法、无 Origin 的写请求（在有令牌后应被令牌拦住）、预检请求、豁免路径。
- 令牌：缺失、错误、正确；常量时间比较（至少测试不泄漏长度差异的行为）；失败限速；轮换后旧令牌失效。
- SSE：经代理携带令牌的订阅；无令牌 401。
- 文件系统：目录浏览的边界；符号链接；超大目录；并发弹窗限制。
- 工作区：`/`、过宽路径被拒绝。
- 错误：每种领域异常到状态码的映射；500 不含堆栈；`trace_id` 在响应头与错误体一致；请求头带入的 `trace_id` 被沿用。
- 回归：新增任何 GET 端点时的评审清单（无副作用）。

## 9. 待定

- 是否支持把 API 暴露给局域网（例如在另一台设备上用浏览器访问）。目前明确不支持。若支持，需要 TLS、独立的账户体系与更严格的沙箱，属于另一类部署，应单独立项。
- 令牌是否分级（只读令牌与读写令牌），便于将来接入只读的监控面板。
- 是否在第一次使用时让用户在界面上确认"此浏览器可信"，作为令牌之外的一次性配对步骤。

## 10. 实现状态

接入闸门是纯 ASGI 中间件（`agent_runtime.api.security.AccessGate`），错误信封与领域异常映射在 `agent_runtime.api.errors`，令牌在 `agent_runtime.api.token`。与上文的差异与补充：

- **令牌**：`aegis token` 打印令牌文件路径，`aegis token --rotate` 轮换；环境变量 `AEGIS_API_TOKEN`（`server.auth.token_env`）优先于文件。令牌不出现在日志、事件、错误体、启动看板（只显示路径）。
- **失败限速**：窗口内失败达到阈值后返回 429 `AUTH_RATE_LIMITED`（连正确的令牌也暂时拒绝，直到窗口滑出）。
- **请求体上限**：声明的 `Content-Length` 超限直接 413；流式超限时让应用看到断开、由闸门给 413（框架会把读体失败包装成 400）。文件保存接口放宽到 `tools.files.write_max_bytes` 的两倍加一点余量。
- **trace id**：沿用请求头里合规（`[A-Za-z0-9._-]{1,64}`）的值，否则生成；响应头与错误体一致。
- **领域异常逐个注册到内层的异常中间件**，所以不会被当成未处理的 500 再抛出；真正未处理的异常只给 `INTERNAL_ERROR` 与 `trace_id`，细节只写日志。
- **目录浏览**只允许配置的根之内的目录，不返回隐藏项，条数有上限，受保护的系统目录与符号链接指向根外都是 422；**原生选择窗口**同一时刻只允许一个（409 `PICKER_BUSY`），装配层未提供时 503。
- **sidecar 也有防护**：`bash_shell` 只接受回环 `Host`，且拒绝带 `Origin` 的写请求（恶意网页向 127.0.0.1 发请求一定带 `Origin`）。
