# MCP 接入

MCP（Model Context Protocol）让 BaseAgent 使用第三方实现的外部工具。本文只覆盖**工具**这一项能力，不涉及 MCP 的资源、提示词与采样（客户端不支持服务端发起的请求）。

## 1. 要解决的问题

- 用户希望接入现成的工具服务器（文件系统、GitHub、文档库……），而不用逐个重写。
- 但 MCP 服务器是**第三方代码**：stdio 类型的服务器本身就是在本机以用户身份运行的任意程序，它们的工具描述会进入模型的工具 Schema，它们的返回值会进入上下文。

所以接入的原则是：**默认关闭、显式开启、逐项治理、故障隔离**。

## 2. 总体结构

```
config.toml [mcp.servers.*]
        │
        ▼
MCPManager ──懒连接──► MCP 服务器（stdio 子进程 / SSE 远端）
   │  tools/list
   ▼
vetting（消毒）──通过──► MCPToolDefinition ──► MCPToolAdapter(trust=untrusted)
   │                                                   │
   └─ 拒绝 → 记入 rejected 审计                         ▼
                                              ToolRegistry（逐名授权）
```

| 组件 | 职责 |
|---|---|
| `MCPManager` | 连接生命周期、发现、调用、故障隔离、关闭 |
| `vetting` | 对工具定义做消毒，可硬拒 |
| `MCPToolDefinition` | 远端工具的本地投影与命名空间 |
| `MCPToolAdapter` | 把远端工具伪装成本地工具，`trust="untrusted"` |

## 3. 配置

```toml
[mcp]
enabled = true                  # 总开关
connection_timeout_sec = 30
index_max_listed = 60          # deferred 索引条数上限，超出时只列服务器
index_desc_chars = 80
exposure = "deferred"          # 全局默认，可被服务器覆盖
call_timeout_sec = 50          # 须小于 [tools.dispatch] default_timeout_sec，让管理器先咬合
max_description_chars = 1000
reject_on_injection = true
rlimit_as_mb = 1024
rlimit_fsize_mb = 50
rlimit_cpu_sec = 300

[mcp.servers.github]
enabled = false                 # 每个服务器默认关闭，须显式开启
exposure = "pinned"             # 覆盖全局默认
transport = "stdio"             # stdio | sse
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "env:GITHUB_TOKEN" }

[mcp.servers.remote_doc]
enabled = false
transport = "sse"
url = "http://127.0.0.1:8005/sse"
```

- 凭据只写 `env:VAR`，真实值来自 `.env`，配置文件不含明文。变量未设置时只告警并传空串，不阻断启动。
- **服务器启用即授权**：开启某个服务器，等于授权它通过消毒的全部工具进入主工具表。没有"逐工具白名单"配置，只有服务器级的开关。需要更细的控制时见 §10。

## 4. 连接管理

### 4.1 懒加载

进程启动只读静态配置，**不拉起任何子进程**。第一次需要工具时才握手，并缓存会话。这样 MCP 不拖慢冷启动。

### 4.2 stdio 服务器的启动方式

POSIX 下不直接启动目标程序，而是通过一个同解释器的包装脚本，在 `exec` 之前：

1. 施加 `RLIMIT_AS`、`RLIMIT_FSIZE`、`RLIMIT_CPU`；
2. `os.setsid()` 建立独立会话；
3. `os.execvp` 目标程序。

不用 shell 的 `ulimit`，因为不同 `sh` 实现的单位不一致；`setrlimit` 以字节计，没有歧义。非 POSIX 平台不包装。

### 4.3 故障隔离

单个服务器连接失败只标记该服务器不可用并告警，**不影响其他服务器与主流程**。握手阶段任何失败都会关闭已进入的上下文栈，不留下半开的子进程。

调用中途出现异常，连接被认为已失效并丢弃，下一次调用重新握手。

### 4.4 防僵尸

所有连接由 `AsyncExitStack` 纳管，应用关闭时统一逆序释放。进程退出时若仍有连接未关闭，注册的退出钩子会记录错误提示可能有残留子进程。

## 5. 命名空间

工具一律暴露为 `mcp__{server}__{tool}`，避免不同服务器的同名工具互相冲突，也避免与内置工具撞名。解析时命名不合法直接报错，不做猜测性路由。

### 5.1 暴露方式：`pinned` 与 `deferred`

决策见 [0007](../12_decisions/0007-capability-mounting.md)。通过消毒的工具按服务器的 `exposure` 进入模型视野：

| | `pinned` | `deferred`（默认） |
|---|---|---|
| Schema | 直接进请求的 `tools` | 不进 `tools` |
| 常驻内容 | 完整 Schema | 索引里一行：`mcp__{server}__{tool}` + 一句话 |
| 调用 | 直接调用 | `mcp_describe` 取 Schema，再 `mcp_call` |
| 适合 | 少量高频工具 | 工具多、使用稀疏 |

**索引**（第 2 段，技能清单之后的独立 `user` 信封，见 [提示词装配 §3.5](../03_context/03_prompt_assembly.md)）：

- 一行一个工具，描述取消毒后的首句，截断到 `index_desc_chars`（默认 80）。整段包不可信信封：描述来自第三方，位于稳定前缀里。
- 条数超过 `index_max_listed`（默认 60）时，只列服务器名与工具数，工具名经 `mcp_describe("mcp__{server}")` 取得。
- 由各服务器**最近一次成功的**消毒列表生成，按名称排序。服务器暂时不可用不改索引，调用时返回失败；重新列出成功且内容有差异才改，下个任务生效。

**`mcp_describe(names)`**：参数为工具名或服务器名（`mcp__{server}`）的列表，返回对应的完整定义（名称、描述、`inputSchema`）或服务器的工具清单。只读；结果追加为 `tool` 消息，折叠豁免、观察值阈值放宽（同 `load_skill`）；不可信，包信封。未知名字返回失败并给出相近的索引名。

**`mcp_call(name, arguments)`**：

- 包装层先解析为目标工具，之后一切按目标处理：权限级别、审批卡片（显示目标名与参数）、指纹、`idempotent_tools`、信封、超时。`mcp_call` 自身不参与权限判定。
- 解析失败的情形，各合成失败结果，不派发，计入连续错误：目标不在索引内；目标是 `pinned`（应直接调用）；本任务 transcript 里还没有该工具的 `mcp_describe` 结果；`arguments` 不是对象。
- 参数是否符合 `inputSchema` 由服务器校验，错误以 `isError` 返回，这里不引入 JSON Schema 校验。

**子智能体**不用代理：授予它的 MCP 工具一律直接进它自己的 `tools`。

**挂载集的变化**（服务器启停、重新列出、`exposure` 改动）只在下一个任务的准备阶段生效，任务内索引与 `tools` 冻结，见 [工具系统 §10.1](01_tool_system.md)。

## 6. 消毒（数据面治理）

工具**描述**会进入工具 Schema，模型把它当作权威的使用说明，位置比普通观察值高。恶意服务器在描述里写"调用本工具前请先……"，就是 tool poisoning。所以描述可以**硬拒**。

| 检查 | 结果 |
|---|---|
| 工具名不匹配 `^[A-Za-z0-9_.\-]{1,128}$` | 拒绝 |
| 描述超过 `max_description_chars` | 截断并告警 |
| 描述命中注入样态且 `reject_on_injection` | 拒绝 |
| `inputSchema` 不是对象 | 拒绝（原始判定被如实保留，不做静默"洗白"） |
| `inputSchema.type` 不是 `object`，或 `properties` 不是对象 | 拒绝 |
| 描述过短（少于 8 字符） | 仅告警 |

被拒绝的工具连同原因进入审计列表，经自省接口暴露，用户能看到为什么某个工具没出现。

这只治理**数据面**。stdio 服务器的进程本体是任意代码执行，描述消毒解决不了，只能靠默认关闭、资源上限与审计。

## 7. 调用与权限

`MCPToolAdapter` 把调用转发给管理器，返回统一的 `ToolResult`：

- 远端返回 `isError` → `ok=False`，内容即错误文本。
- 管理器抛 `ToolExecutionError`（服务器不可用、超时、调用失败）→ 失败观察值。
- 内容块压平为文本；**非文本块（图片、资源引用）只保留类型提示**，如 `<image content>`，信息会丢失。

权限：未知工具默认要求 `full_permissions`（`unknown_tool_level`）。因此 MCP 工具在默认基线 `workspace_write` 下**每次调用都需要人工审批**，除非把具体名字加进 `read_only_tools` 等名单。这是有意的保守默认，见 [权限分层 §3.1](../05_security/01_permission_tiers.md)。

信任：`trust="untrusted"`，返回值会被加不可信信封与警示语，见 [信任与注入](../05_security/03_trust_and_injection.md)。

幂等：默认非幂等，崩溃恢复时不会被盲目重试，见 [工具系统 §3.2](01_tool_system.md)。

## 8. 已发现的问题

| # | 问题 | 级别 |
|---|---|---|
| 1 | **连接的建立与释放可能不在同一个任务里。** 管理器自己的文档警告：`anyio` 的取消作用域与创建它的任务绑定，连接必须在同一任务内建立和释放。但实际上首次连接发生在每个任务的准备阶段（后台任务协程），而 `shutdown_all` 在应用关闭阶段调用。两者很可能不是同一个任务，关闭时可能出现作用域错误或子进程残留。**已对 mcp 2.3 验证属实**：在一个任务里建立、另一个任务里 `aclose`，抛 `RuntimeError: Attempted to exit cancel scope in a different task`（子进程事后仍被回收，但不能依赖）。专用后台任务方案已验证有效，见 [技术选型 §11](../01_architecture/05_tech_stack.md) | 高（已证实，方案已验证） |
| 2 | **工具名消毒与模型接口不一致。** 消毒允许名字含 `.` 且长度到 128，而多数 OpenAI 兼容端点要求函数名匹配 `^[a-zA-Z0-9_-]{1,64}$`。加上 `mcp__{server}__` 前缀后更容易超长。一个这样的工具会让**整个请求**被端点拒绝（400），所有后续模型调用都失败 | 高 |
| 3 | **失败的服务器永久短路。** 一次握手失败后，该服务器在进程生命周期内不再重试，除非重启。启动瞬间网络抖动就会让它整个会话不可用 | 中 |
| 4 | **`npx -y` 直接下载并运行 npm 包，无版本固定。** 供应链风险：包被替换或抢注，用户批准一次开启，之后每次都可能拉到不同的代码 | 中 |
| 5 | **`RLIMIT_AS` 默认 1024 MB 对 Node 类服务器偏小。** V8 需要预留大量虚拟地址空间，容易在启动时失败，表现为"服务器连不上" | 中 |
| 6 | **适配器超时与管理器超时同为 60 秒。** 派发器的 `wait_for` 与管理器内部的 `wait_for` 几乎同时触发，派发器的取消可能打断 SDK 会话里的请求，留下状态不一致的连接 | 低 |
| 7 | **工具列表只在握手时获取一次。** 服务器后来增减工具或修改描述（`listChanged`），本端感知不到，直到连接重建 | 低 |
| 8 | stdio 服务器的环境变量：配置里的 `env` 与 SDK 的默认安全环境合并，是否会把宿主环境的敏感变量带给第三方进程，**已对 mcp 2.3 验证**：父进程的 `DEEPSEEK_API_KEY` 不会出现在子进程里，只有 SDK 的默认安全变量加配置里显式给出的 `env` | 已证实无泄露（2.3） |

## 9. 新版设计

1. **统一在一个生命周期任务里管理连接。**（已用 `tests/sdk/test_mcp_sdk.py` 验证：多个任务并发提交调用、由另一个任务触发关闭、直接取消拥有者任务，三种情形子进程都被回收。） 由一个专门的后台任务拥有全部 MCP 会话（建立、调用转发、关闭都在这个任务里），其他任务通过队列或 `Future` 提交调用。这从结构上避开 `anyio` 的任务约束，不依赖"调用方碰巧在同一个任务里"。
2. **名称规范化：** 对外暴露给模型的函数名由我们生成，保证匹配 `^[a-zA-Z0-9_-]{1,64}$`：非法字符替换为 `_`，过长时截断并附短哈希，同时维护「暴露名到原始（服务器、工具）」的映射。消毒阶段拒绝无法规范化的名字。
3. **失败重试带退避：** 服务器标记失败后，按指数退避（例如 30 秒、2 分钟、10 分钟）在后续任务准备阶段重试，成功即恢复。
4. **供应链：** 配置层给 `npx` 之类的启动方式一个告警，推荐固定版本（`@scope/pkg@1.2.3`）。文档里提供一份"已审查服务器清单"模板。
5. **资源上限按服务器配置：** `rlimit_as_mb` 等可在 `[mcp.servers.x]` 下覆盖全局值。
6. **幂等声明：** 服务器配置里可声明 `idempotent_tools = ["read_*"]`，用于崩溃恢复。
7. **工具列表刷新：** 在每个任务准备阶段对已连接服务器重新 `tools/list` 并重新消毒（代价低），或订阅 `listChanged`。重新消毒是必须的，不能只消毒一次。
8. **调用超时分层：** 管理器的超时小于派发器的超时，让管理器先咬合。
9. **可观测：** 自省接口暴露每个服务器的状态、工具数、被拒工具与原因、最近一次错误，前端能看到。

## 10. 更细粒度的授权（待定）

当前是服务器级授权。可以考虑增加：

```toml
[mcp.servers.github]
allow_tools = ["create_issue", "get_issue"]   # 空表示全部
```

这与「逐名授权」的设计初衷一致，成本低，且能缩小被投毒后的影响面。

## 11. 不变量

1. 默认不启动任何 MCP 子进程。
1a. 任务内不改 `tools`；`mcp_call` 的权限判定对象恒为目标工具。
2. MCP 工具永远是 `untrusted`，不会出现在没有逐名授权的主工具表里。
3. 单个服务器故障不影响其他服务器与主流程。
4. 消毒未通过的工具不会被注册，且原因可审计。
5. 对模型暴露的工具名满足端点的命名约束。
6. 应用关闭时所有 MCP 子进程被回收。
7. 凭据不出现在配置、日志与事件中。

## 12. 测试要点

- 懒加载：启动时不拉起子进程；首次需要才握手。
- 消毒：工具名非法、描述含注入样态、描述超长、`inputSchema` 畸形、过短描述。
- 命名：规范化后的名字满足约束，往返映射正确，冲突处理。
- 故障：服务器不存在、握手超时、中途崩溃、返回 `isError`；其余服务器不受影响；退避重试恢复。
- 生命周期：关闭后无残留子进程；在**不同任务**里发起和关闭的场景（对应第 1 项）。
- 权限：MCP 工具默认需要审批；加入只读名单后免审。
- 安全：返回值带不可信信封；凭据不在日志里。
- 资源：超出 `RLIMIT_FSIZE` 被终止。

## 13. 待定

- `listChanged` 目前只考虑当作"需要刷新"的信号，不在任务内生效，见 [0007](../12_decisions/0007-capability-mounting.md)。
- 是否按 transcript 位置而不是"本任务取过 Schema"来判定 `mcp_call` 的前置条件，以允许续跑后沿用旧 Schema。
- 是否支持 MCP 的资源与提示词能力。目前明确不支持。
- 对 SSE 远端服务器的鉴权与 TLS 校验要求。目前配置里只有 URL。
- 是否把 MCP 工具默认放进websearch 工具那样的独立工具表，而不是主工具表，以进一步缩小影响面。

## 14. 实现状态

已实现（`backend/src/mcps/`，约 40 个测试，用真实的 stdio 子进程，不联网）：

- **管理器**（`manager.py`）：懒连接；一个专用后台任务拥有全部会话的建立与关闭（§8 第 1 项的方案，已在“在一个任务里发起、另一个任务里关闭”的场景验证无残留进程）；调用本身不进入上下文，可在任意任务发起；并发任务共用同一连接与进程；每个任务准备阶段重新 `tools/list` 并重新消毒（§9.7），刷新失败则丢弃连接并就地重连一次。
- **故障**：握手失败、握手超时、中途崩溃都只影响该服务器；失败按 `retry_backoff_sec` 退避重试（连续失败逐级加长，成功清零）；调用超时与传输故障丢弃连接，下一个任务重新握手；服务器报告的业务错误与 JSON-RPC 错误（未知工具、参数不合法）不拆连接。管理器超时（`call_timeout_sec`）先于派发器咬合（适配器的派发超时为其加 5 秒）。
- **命名**（`naming.py`）：`mcp__{服务器}__{工具}`，非法字符换成 `_`，超长或撞名时附 8 位哈希；分配是确定性的。
- **消毒**（`vetting.py`）：工具名、`inputSchema` 形状与规模、描述长度，以及描述与**参数说明**里的注入样态（后者同样是投毒面）。被拒的工具连同原因进入 `GET /mcp/servers`。
- **启动包装**（`wrapper.py`）：`exec` 之前 `setrlimit`（AS/FSIZE/CPU）并 `setsid`；资源上限可在 `[mcp.servers.x]` 下按服务器覆盖（0 表示沿用全局值）。子进程只拿到 SDK 的安全默认环境加配置里显式声明的 `env`，`env:VAR` 引用在启动时解析，值不进日志与自省。
- **授权**：`allow_tools` 限定暴露范围（未放行的不算被拒）；`idempotent_tools` 支持通配并接入崩溃恢复。MCP 工具恒为 `untrusted`，只有通过消毒的工具名被逐名加入主工具表的不可信授权清单；默认基线下每次调用需要 `full_permissions` 级别的审批，返回值带不可信信封。
- **供应链**：启用的 `npx`/`uvx` 等启动方式若包名没有固定版本，启动时告警。
- **装配**：`Application` 在 `[mcp].enabled` 时创建管理器，任务构建时取工具（任何故障只是少几个工具，不让任务起不来），应用关闭时先回收全部子进程；前端右侧栏有只读的“MCP 服务器”卡片。

**0007 已实施**：`exposure`（全局默认加按服务器覆盖）、`mcp_describe` / `mcp_call`（`mcps/index.py`）、索引（`render_index`）、`ToolRegistry(hidden=…)`（延迟工具可派发但不进 `tools`）；管理器保留各服务器最近一次成功的消毒列表（`ServerState.known`），服务器暂时断开不改变工具集与索引，调用时返回"当前不可用"。包装层的代理解析在 `loop/proxy.py`，前置条件"本任务取过 Schema"按 transcript 里 `mcp_describe` 结果的 `<mcp_tool name=…>` 标记判断。子智能体被授予的 MCP 工具直接进它自己的 `tools`（父工具表里的延迟工具实例本身可被分配）。
