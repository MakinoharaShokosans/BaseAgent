# 内置工具

内置工具是主 Agent 开箱即用的可信工具。本文列出每个工具的行为、边界与已知缺口。装配规则见 [工具系统 §10](01_tool_system.md)。

## 1. 清单

| 工具 | 作用 | 权限级别 | 幂等 | 状态 |
|---|---|---|---|---|
| `view_file` | 带行号读取工作区文件片段 | read_only | 是 | 已有 |
| `write_file` | 写入工作区文件 | workspace_write | 否（待定） | 已有 |
| `bash` | 在工作区执行 Shell 命令 | 按命令分类 | 否 | 已有，见 [Shell 工具](03_shell_tool.md) |
| `load_skill` | 载入技能 SOP | read_only | 是 | 已有，见 [Skills](05_skills.md) |
| `read_artifact` | 读取本任务被裁剪的完整输出 | read_only | 是 | **新增** |
| `edit_file` | 对文件做精确的局部替换 | workspace_write | 否 | **建议新增** |
| `delegate_research` | 受控的外部检索 | read_only | 否 | 已有，见 [研究隔离区](../06_subagents/01_research_isolation.md) |
| `spawn_subagent` | 动态委派 | read_only（动作本身） | 否 | 已有，见 [动态委派](../06_subagents/02_dynamic_delegation.md) |

`rag_search` 与 `delegate_code_search` 随 RAG 一起移除。

## 2. view_file

**作用**：读取工作区内文件的指定行范围，返回带行号的文本。

| 参数 | 说明 |
|---|---|
| `path` | 相对工作区根的路径（必填） |
| `start_line`、`end_line` | 起止行，从 1 开始 |

行为：

- 路径经 `resolve()` 后必须位于工作区内，越界返回失败观察值，见 [工具系统 §11](01_tool_system.md)。
- 单次最多 400 行。超出时末尾提示"如需后续内容请递增 `start_line`"。
- 按 UTF-8 解码，`errors="replace"`：二进制文件不会让工具崩溃，但内容会是乱码。
- 起始行超出总行数返回失败，并告知总行数。
- 超时 15 秒。

缺口：

1. **整个文件读入内存再切片。** 一个几百兆的日志文件会占用大量内存。应改为按行流式读取到目标范围即停止，并设置文件大小上限（例如超过 10 MB 拒绝全量读取，只允许指定行范围）。
2. **不识别二进制。** 读图片或编译产物会得到一堆替换字符，白白占用上下文。应检测空字节或高比例非文本字节，返回"疑似二进制文件，大小 N 字节"。
3. **没有目录列表能力。** 模型只能靠 `bash ls`、`find` 浏览目录。去掉 RAG 后这一点更突出，见 §6。

## 3. write_file

**作用**：整文件写入（覆盖）。

| 参数 | 说明 |
|---|---|
| `path` | 相对路径 |
| `content` | 完整的新文件内容 |

行为：路径校验同上；自动创建父目录；单次内容不超过 1,000,000 字节；UTF-8 写入；返回"已写入 path（N 字符）"。

缺口：

1. **非原子写入。** 直接 `write_text`，写到一半进程崩溃会留下残缺文件。应先写临时文件再 `os.replace`。
2. **不保留文件权限与换行风格。** 覆盖一个可执行脚本会丢掉执行位；覆盖 CRLF 文件会变 LF。至少应当保留原有权限位。
3. **整文件覆盖对大文件的小改动代价高。** 模型必须把整个文件重新输出一遍，浪费 Token 且容易在不相关的部分引入改动。这是新增 `edit_file` 的主要原因。
4. **没有"改前必须先读"的硬约束。** 系统提示词要求先 `view_file`，但工具本身不检查。可选的强化：要求覆盖已有文件时附带上一次读取时的文件摘要（哈希），不一致则拒绝，避免覆盖用户在期间做的修改。
5. 覆盖已有文件**没有任何备份**。用户的工作区里的未提交修改一旦被覆盖就无法找回。建议在写入前对被覆盖的文件在任务产物目录里留一份副本（`artifacts/{task_id}/overwritten/…`），成本低，价值高。

## 4. read_artifact（新增）

解决"被裁剪的观察值无法取回"的问题，设计见 [观察值治理 §6](../03_context/01_observation_governance.md)。

```
read_artifact(artifact_id, start_line?, end_line?, grep?)
```

- 只接受 `state.artifacts` 里登记的 id，不接受路径。
- 分页规则与 `view_file` 相同，单次最多 400 行。
- `grep` 为可选正则，只返回匹配行及行号（上限 200 行）。
- 产物的原工具信任级随产物一起记录；原工具不可信时读取结果同样带不可信信封。
- 不能读取其他任务的产物。

## 5. edit_file（建议新增）

```
edit_file(path, old_string, new_string, replace_all=false)
```

- `old_string` 必须在文件中**恰好出现一次**（除非 `replace_all`），否则失败并说明出现次数，让模型补充上下文使其唯一。
- 原子写入，保留权限位。
- 失败时给出最接近的候选片段（可选），帮助模型修正。
- 权限级别同 `write_file`。

这是目前代码修改场景里最有价值的一个缺口：局部精确修改既省 Token，又避免整文件重写带来的副作用。

## 6. 去掉 RAG 之后的代码定位

旧版靠 `rag_search` 做语义检索；去掉之后，定位代码完全依赖 `bash` 中的 `grep`、`rg`、`find`、`ls` 和 `view_file`。要让这套组合足够好用：

1. 在环境里确保 `rg`（ripgrep）可用，并在启动自检里检查，缺失则回退到 `grep -rn`，见 [Shell 工具 §4](03_shell_tool.md) 的命令规范。
2. 考虑新增只读的 `list_dir(path, depth=2, max_entries=200)`，自动忽略 `.git`、`node_modules`、`__pycache__` 等噪音目录，比让模型反复拼 `find` 命令更稳。
3. 考虑新增 `grep` 内置工具包装 `rg`：参数结构化（pattern、path、glob、context 行数、最大条数），输出统一格式并自带截断，权限级别 `read_only`，**不经过 shell**，避免命令注入与分类歧义。
4. 大范围阅读由 `spawn_subagent` 承担：授予 `bash`/`grep` 与 `view_file`，在独立上下文里搜索，只带回带引用的结论。
5. 技能 `workspace_explorer` 已提供一套"先宏观、后局部"的勘测流程，需要把其中的搜索步骤对齐上面的工具。

`list_dir` 与 `grep` 两个结构化工具的好处在于：它们的权限判定是**确定的**（工具名即只读），不依赖对命令文本的正则分类。

## 7. 工具描述的写法

工具的 `description` 直接决定调用准确率，是提示词的一部分。约定：

- 第一句说明作用；第二句说明关键约束（路径必须在工作区内、单次返回上限）。
- 写明失败时的行为，让模型知道该怎么修正。
- 不在描述里写策略性的指令（如"总是先调用 X"），那属于系统提示词与技能。
- 描述中的首行会出现在 planner 的能力清单里，所以首行必须自成一句。

## 8. 不变量

1. 所有文件类工具的路径都经同一个校验函数。
2. 任何文件类工具都不跟随符号链接逃逸出工作区。
3. 工具对业务失败返回失败观察值，不抛异常。
4. 写类工具不得静默地丢失用户数据（原子写入加覆盖前备份）。
5. 每个工具声明 `timeout_sec`，且值与其预期耗时匹配。

## 9. 测试要点

- 路径：`..`、绝对路径、符号链接指向工作区外、符号链接指向工作区内。
- `view_file`：行范围边界、超过 400 行的分页提示、起始行越界、二进制文件、超大文件。
- `write_file`：创建父目录、超过大小上限、崩溃模拟下原子性（写到一半中断不留残缺文件）、权限位保留、覆盖前备份存在。
- `edit_file`：唯一匹配、零匹配、多匹配、`replace_all`、换行风格保留。
- `read_artifact`：越权、分页、`grep`、不存在的 id。
- `list_dir`、`grep`：忽略规则、条数上限、非 UTF-8 文件。

## 10. 待定

- `write_file` 是否声明为幂等。
- 是否内置 `list_dir` 与 `grep`，还是只靠 `bash`。倾向内置，理由见 §6。
- 文件监视：任务期间用户在外部修改了文件，Agent 如何得知。目前不支持，写入前的哈希校验是最小可行的保护。

## 11. 实现状态

已实现：`view_file`、`write_file`、`read_artifact`、`load_skill`、`bash`（见 [Shell 工具 §8](03_shell_tool.md)、[Skills §14](05_skills.md)）。`edit_file`、`list_dir`、`grep` 也已实现（见 §13）。

相对上文的差异与补强：

- **`view_file` 流式读取。** 按行迭代到目标范围之后继续数总行数，不整文件读入内存；未指定行范围且文件超过 `view_max_file_mb` 时拒绝并提示指定范围；前 8 KB 含空字节判为二进制，返回“疑似二进制文件，大小 N 字节”（§2 缺口 1、2 已补）。`end_line` 超过单次上限时同样被截断并给出续读提示。
- **`write_file` 原子写入。** 写同目录临时文件再 `os.replace`，失败时临时文件被清掉、原文件不动；保留已有文件的权限位；不做换行转译（按字节写入，CRLF 内容原样保留）；大小上限按**字节**计，不按字符。覆盖已有文件前若配置了备份目录（`backup_overwritten`，默认 `artifacts/{task_id}/overwritten/<相对路径>`，重名加 `.1`、`.2`），先拷贝一份；**备份失败则不写**，因为“不得静默丢失用户数据”比“写成功”重要（§3 缺口 1、2、5 已补；缺口 4 的哈希校验未做）。
- **路径沙箱只有一个函数。** `resolve_within_root`：相对路径按根解释、`resolve()` 之后必须在根内；目标尚不存在时也成立（指向工作区外的符号链接目录之下的新文件同样被拦）。空串、NUL 字节、符号链接环都报“路径不可用”。
- **`read_artifact`。** `TaskArtifacts` 是任务绑定对象：`tool_runner` 每次进入时把 `state.artifacts` **整体替换**推给它（`ToolRunnerDeps.bind`），别的任务的产物不会残留；只接受已登记的 id（可带 `artifact://` 前缀），失败时列出已有 id 但不暴露路径；即使登记表被篡改，解析后的路径也必须在产物根目录内，符号链接指到外面同样被拒。`grep` 给出时忽略行范围，每行最多匹配前 2000 字符，结果上限 `grep_max_results`。
- **产物来源信任。** 登记表里只有 `id -> 路径`，所以来源工具从句柄推：`obs_step_{n}_{工具}` 与 sidecar 的 `step_{n}_{工具}`。同一步的重名后缀（`_2`）与带数字的工具名分不开，所以**两种读法都在可信名单里才算可信**，认不出来源的取不可信；代价是同一步第二个 `bash` 的产物多包一层信封，无害。
- **`tool_runner` 登记工具自带的产物。** 工具结果里带 `artifact_id` 与 `artifact_path`（sidecar 的命令日志）时登记进同一张表（重名加后缀，不覆盖），被截断时在观察值末尾追加 `[完整输出: artifact://…]`。这统一了 sidecar 日志与裁剪器两套句柄（观察值治理 §6.1 的最后一条）。
- **`load_skill`** 的信封、转义与不可信标注见 Skills §14。

已知缺口：

1. `view_file` 在大文件上为了数总行数仍会扫到文件末尾（流式、不占内存，但耗时与文件大小成正比）。
2. `read_artifact` 的 `grep` 是 Python 正则，没有单次匹配的时间上限；整个调用靠派发器的 15 秒硬超时兜底，线程里的匹配被取消后仍会跑完。
3. `write_file` 的备份目录没有清理策略，依赖产物目录的整体保留期。


## 13. edit_file、list_dir、grep 的实现

- **`edit_file`**：`old_string` 必须恰好出现一次，否则失败并说明出现次数与行号；`replace_all` 替换全部。零匹配时给出最接近的一行与行号。文件是 CRLF 而 `old_string` 不是时，按文件的换行风格转换后再匹配。原子写、保留权限位、覆盖前备份（备份失败则不写）。修改后超过 `write_max_bytes` 失败。
- **`list_dir`**：目录在前、深度 1-6（缺省 2）、条数上限取配置；忽略 `tools.files.ignored_dirs` 与隐藏项；指向工作区外的符号链接不展示。
- **`grep`**：纯 Python 正则（不依赖 `rg`，行为确定），支持 `glob`、`context`（0-5）、`ignore_case`、`fixed`；跳过噪音目录、二进制文件与超过 `view_max_file_mb` 的文件；命中数与 10 秒预算双重上限，截断时提示；不跟随指向工作区外的链接。输出 `路径:行号:内容`，上下文行用 `-` 分隔。
- 三者的权限判定都是确定的（`list_dir`、`grep` 是只读，`edit_file` 是工作区写入），不依赖对命令文本的分类。

## 14. 写入后的即时语法诊断

`write_file` 与 `edit_file` 成功写入后，对 `.py`/`.pyi`、`.json`、`.toml` 做进程内解析（`ast` / `json` / `tomllib`，不启动子进程、不执行内容），有语法错误就在**这次的观察值末尾**追加一行 `[语法检查] 路径 现在有语法错误（第 N 行：…），请立即修复。` 写入照常完成（结果仍是成功，文件已落盘），模型不必等到跑测试才发现改坏了。没有对应解析器的扩展名不诊断，不代表没问题；超过 20 万字符的内容不检查。实现：`tools/builtin/diagnostics.py`。
