# Shell 工具与命令规范

`bash` 工具是 Agent 侧的薄封装：组装参数、转译结果。**沙箱、审计、资源限制都在 sidecar 里**，见 [Shell 沙箱](../05_security/02_shell_sandbox.md)。权限判定见 [权限分层](../05_security/01_permission_tiers.md)。本文覆盖两件事：Agent 侧的工具行为，以及写给模型的命令使用规范。

## 1. 工具行为

```
bash(command, timeout_sec?)
```

| 项 | 行为 |
|---|---|
| 工作目录 | 工作区根目录 |
| 超时 | 默认 60 秒，可由参数覆盖；超时后进程组被两段式硬杀 |
| 标准输入 | 关闭（`/dev/null`），命令无法等待交互 |
| 输出 | sidecar 先蒸馏，全文落盘；模型看到的是头尾加关键行 |
| 退出码 | 非零时 `ok=False`，但观察值仍然完整可用 |
| 排队 | 并发配额满时返回"已进入等待队列，请稍后重试"，标记 `ok=True`，不计入连续错误 |
| 步号 | 工具内部单调递增计数，用于日志命名，不泄漏编排层的步号 |

缺少 `command` 返回失败；`timeout_sec` 非法时回退默认值。

### 1.1 结果的转译

| sidecar 字段 | 进入 `ToolResult` |
|---|---|
| `distilled_stdout` / `distilled_stderr` | 拼成 `content`，都为空则为"（无输出）" |
| `exit_code` | `exit_code`；`ok = (exit_code == 0)` |
| `artifact_path` | `artifact_path`，句柄取文件名 |
| `is_truncated` | `is_truncated` |
| `execution_time_ms` | `meta` |

### 1.2 失败的两类原因要分开

| 情形 | 现状 | 应有的表现 |
|---|---|---|
| sidecar 不可达、超时 | 失败观察值，"sidecar 不可达" | 同左 |
| 命令被审计拒绝（403）、路径越界（422） | 被当作"sidecar 异常状态码"，**原因丢失** | 失败观察值要带规则与原因，如"命令被安全策略拒绝：禁止递归强制删除根目录" |

第二类是现有缺口，见 [沙箱 §5.2](../05_security/02_shell_sandbox.md)。新版里 `bash` 对 403 与 422 单独处理，把 `reason` 与 `rule` 放进观察值，并**不计入连续错误**的"依赖故障"类别（它是策略拒绝，不是基础设施故障），但仍然会被死循环检测看到，避免模型反复提交同一条被拒命令。

## 2. 命令使用规范（给模型）

下面这些写进 `bash` 工具的描述或一个常驻的内置技能里，减少无效调用。

### 2.1 必须非交互

- 没有标准输入，**不要**运行需要交互的命令（`python` 不带参数、`vim`、`less`、`git commit` 不带 `-m`、`npm init`、`ssh`）。
- 分页器会卡住：`git log` 用 `git --no-pager log -n 20`，或加 `| cat`。
- 需要确认的命令加非交互开关（`-y`、`--yes`、`--no-input`），但安装类命令本身需要审批。

### 2.2 控制输出体积

- 先估量再读：`wc -l file`、`ls -la`、`git status --short`。
- 大文件不要 `cat`。读片段用 `view_file`，或 `sed -n '120,180p' file`、`head -n 50`、`tail -n 50`。
- 搜索结果加条数限制：`rg -n --max-count 5 pattern`，或 `| head -n 50`。
- 编译与测试输出只关心结论：`pytest -q -x`，失败时再看详情。输出会被蒸馏，但蒸馏有信息损失，能在源头限制最好。

### 2.3 代码定位（去掉 RAG 之后的主要手段）

| 目的 | 命令 |
|---|---|
| 目录概览 | `ls -la`、`find . -maxdepth 2 -not -path '*/.git/*' -not -path '*/node_modules/*'` |
| 找符号定义 | `rg -n "def foo\b|class Foo\b" --glob '*.py'` |
| 找引用 | `rg -n "\bfoo\(" --glob '*.py'` |
| 找文件 | `rg --files | rg 'config'` 或 `find . -name '*config*' -not -path '*/.git/*'` |
| 看某文件的函数列表 | `rg -n "^\s*(def|class) " path/to/file.py` |
| 看最近改动 | `git --no-pager log --oneline -n 20`、`git --no-pager diff --stat` |
| 统计规模 | `rg --files | wc -l`、`wc -l $(git ls-files '*.py') | tail -1` |

要点：优先 `rg`，不可用时退回 `grep -rn`；总是排除 `.git`、`node_modules`、`__pycache__`、`.venv`、`dist`、`build`；用 `\b` 和 `--glob` 缩小范围。

### 2.4 组合命令

- 一行里串联多个相关的只读命令，比分多轮调用省轮次。例如 `ls && git status --short && head -n 20 README.md`。
- 但**不要把有副作用的操作和只读探测混在一条里**：权限判定是按整条命令文本分类的，混在一起会整体升级到更高档，触发不必要的审批。

### 2.5 避免被拦或被审批

| 想做的事 | 建议 |
|---|---|
| 写文件 | 用 `write_file` 或 `edit_file`，不要 `echo > file` / `cat <<EOF > file`（后者依赖重定向，被归为写入类，且容易转义出错） |
| 删除 | 删单个具体文件，避免 `rm -rf` 加通配 |
| 联网 | 不要自己 `curl`；外部资料走 `delegate_research`。网络命令需要全权限审批 |
| 安装依赖 | 需要审批。先确认确实缺依赖（读 `pyproject.toml`、`package.json`） |
| `git push`、`sudo`、`docker` | 全权限，需要审批 |
| 绕过 | 被拒绝后**不要**换个写法重试（拆分命令、改写参数、借脚本间接执行）。系统会把这视为违规，应改用合规方案或如实报告 |

### 2.6 长时间运行的命令

- 默认 60 秒超时。构建与测试可能更久，用 `timeout_sec` 显式放宽（上限由沙箱配置的硬超时决定）。
- **不要启动常驻进程**（开发服务器、监听器）。没有后台执行与进程管理，进程会占用沙箱槽位直到超时被杀。需要验证服务时，用短时的一次性请求（启动、探测、退出写在一条命令里并带 `timeout`）。
- 并发配额满时会收到"已进入等待队列"，应稍后重试或减少并行命令，而不是立刻重发。

### 2.7 错误处理

- 命令失败时先看**报错的最后几行**与关键行，不要重复同一条命令。重复相同命令连续三次会被死循环检测拦下。
- 退出码非零但输出为空，多半是命令本身有问题（拼写、参数）；加 `2>&1` 看 stderr 不是必须的，因为 stdout 与 stderr 都会返回。

## 3. 把规范放在哪里

不放进每次都发送的系统提示词（占预算），而是：

1. `bash` 工具描述里放最关键的三条：非交互、控制输出、被拒后不要绕过。
2. 其余放进一个内置技能 `shell_best_practices`，按需 `load_skill`。
3. 系统提示词里只留一句指向技能的提示。

## 4. 环境自检

启动时做一次轻量检测，写入工作区层的环境信息或自检接口：

| 检测 | 用途 |
|---|---|
| `rg` 是否可用 | 决定提示里推荐 `rg` 还是 `grep -rn` |
| `git` 是否可用，工作区是否是仓库 | 决定 `git` 相关建议是否出现 |
| `python`、`node`、`make` 等常用工具的版本 | 减少模型试探性调用 |

自检结果是**数据**，不进入权限判定。

## 5. 不变量

1. Agent 侧不做任何沙箱判断，边界只在 sidecar。
2. 策略拒绝的原因必须到达模型。
3. 排队不计入连续错误；策略拒绝不计入基础设施故障计数。
4. 观察值总是经过蒸馏，全文可通过 `read_artifact` 取回。

## 6. 测试要点

- 参数：缺失 `command`、非法 `timeout_sec`。
- 结果转译：成功、非零退出码、信号终止、超时、排队、空输出。
- 错误区分：sidecar 不可达与策略拒绝的观察值不同，后者含规则与原因。
- 步号：多次调用单调递增，且与编排层步号无关。
- 规范：用一组"典型任务"回放，检查模型没有使用交互命令、分页器、常驻进程（属于评测，非单元测试）。

## 7. 待定

- 是否提供受控的后台进程能力（启动、查看输出、终止），以支持"启动服务再测试"的场景。它会显著扩大攻击面和资源管理复杂度，暂不纳入首版。
- 命令历史是否作为上下文的一部分提供给模型，用于避免重复探测。

## 8. 实现状态

`BashTool` 与 `SidecarClient` 已实现（sidecar 服务本身未做，目前只有客户端与契约）。与上文的差异与细节：

- **响应契约**：`ShellResponse` 对多余字段与未知 `status` 直接报错，转成“sidecar 返回了无法识别的响应”，不信任漂移的契约。
- **超时**：`timeout_sec` 超过 `max_timeout_sec` 时夹到上限；非数字、非正数、布尔值回退默认（不报错，模型多半只是写错类型）。工具自己的硬超时取 `max_timeout_sec + 15 秒`，否则派发器会抢在 sidecar 之前把命令判成超时。
- **`ok` 的判定**：有退出码时看 `exit_code == 0`；没有时看 `status == SUCCESS`；`TIMEOUT` 或 `timed_out` 一律失败，观察值保留已有输出并追加“命令执行超时（超过 N 秒），已被终止”。
- **排队**：`QUEUED` 为 `ok=True`、无退出码，所以 `ToolResult.failed` 为假，不计入连续错误；预估等待写进观察值。
- **策略拒绝（§1.2）**：403 与 422 单独处理，规则与原因放进观察值，`meta.policy_rejected=True`，并带 `rule`。它们**仍然是失败**（`ok=False`，计入连续错误：这是模型的失误，不是基础设施故障），与“sidecar 不可用”（`meta.dependency_unavailable=True`）区分；死循环检测照常看得到反复提交的同一条被拒命令。原因从 `detail` 的字典、列表、字符串或顶层字段里取，取不到时仍明确说“被安全策略拒绝”。
- **产物**：`artifact_id` 取日志文件名去扩展名（`step_3_bash`），`tool_runner` 把它登记进 `state.artifacts`（见 [内置工具 §11](02_builtin_tools.md)），摘要里带句柄，全文可用 `read_artifact` 取回（§5 第 4 条成立）。
- **输出拼接**：stdout 在前，stderr 以 `[stderr]` 标题随后；都为空是“（无输出）”。

**未做**：环境自检（§4）、`shell_best_practices` 内置技能（§3）、sidecar 服务端。
