# 动态委派

主 Agent 可以用 `spawn_subagent` 临时组建一个受限的子劳动力，去完成一个需要阅读大量材料、但只需回流简短结论的子任务。与websearch 工具不同，它的工具集与权限是**每次派发时动态决定**的。

## 1. 要解决的问题

- 有些子任务（通读十几个文件找出某个调用链）会产生大量中间观察值，放进主上下文既浪费又干扰。
- 让模型自己组建子劳动力意味着：**模型提出的授权请求，本身可能就是被注入的**。设计必须假设主 Agent 会尝试给自己发能力。

## 2. 第一原则：能力衰减，而非能力授予

`spawn_subagent` 的入参是主模型生成的，它是一份**提议**，不是授权。三道收窄在派发之前一次性完成：

| 收窄 | 规则 | 失败处理 |
|---|---|---|
| ① 工具集 | 申请的工具必须是**派发时刻**父工具表的子集；剔除 `spawn_subagent` 本身和 `denied_tools`；条数不超过 `max_assigned_tools`（默认 6） | **全有或全无**，有任何一项不合规整体拒绝，不做静默收窄 |
| ② 权限级别 | 取父级当前权威级别（来自任务授权窗口），子级不可升级 | 子级内部越级即失败 |
| ③ 深度 | `当前深度 + 1 ≤ max_depth`（默认 1），且工具表里剔除本工具 | 拒绝并提示自行完成 |

进入子智能体之后，它面对的是一个**已经定死的世界**：没有可扩张的接口，它内部的行为不需要再被信任。信任决策被收敛到边界上的一次，而不是分散在内部每次调用上。

### 2.1 为什么"全有或全无"

静默收窄会让主 Agent 以为子智能体拥有某项能力而实际没有，子智能体按错误假设工作，失败原因难以追查。整体拒绝并列出当前可授权的工具，让主 Agent 一次改对。

### 2.2 `denied_tools` 的作用

默认黑名单包括 `spawn_subagent`、`websearch`。这是两件事的硬防线：防止套娃，防止模型嵌套调用模型造成不可控的循环。深度限制与黑名单双重保证。

## 3. 派发流程

```
提议（role, goal, assigned_tools）
   │
   ├─ 目标为空？                   → 失败
   ├─ 深度超限？                   → 失败
   ├─ assigned_tools 为空？        → 失败（不提供默认授权，不给就是没有）
   ├─ 工具集收窄 + 条数检查         → 整体拒绝或通过
   ├─ 构造子工具表
   └─ 运行 SubagentRunner
```

其中角色代号与目标按长度裁剪（120 与 1200 字符），再进入子级系统提示。

### 3.1 输入收敛

- 子级工具表是独立实例，**镜像父表的不可信授权策略**，父表允许什么是唯一上限，子表不会自己放宽。

## 4. 子智能体的执行循环

与主循环同形的一次嵌套 `run`（[主循环](../02_runtime/02_main_loop.md)），差别只在：独立的 transcript、收窄后的工具集、不请求审批。没有步数、Token、挂钟上限；用户取消父任务时取消随之传到子级。

```
循环：
    调用模型（带子工具表的 Schema）
    没有工具调用 → 退出
    逐个调用做权限判定 → 越级的合成失败观察值，其余按主循环规则派发
    工具观察值按字符截断后加信封追加
收尾提炼：不带工具，强制 JSON，产出结构化报告
```

### 4.1 越级即失败，绝不挂起

子级每次调用仍用 [权限判定](../05_security/01_permission_tiers.md) 逐次检查（同一工具、不同入参级别不同，例如 `bash` 的命令分类，只能在这里判定）。越级的调用直接合成失败观察值，告诉子智能体"需要的权限没有授予，且你不能发起审批"，并向事件流发 `subagent.blocked`，这是用户最需要看到的事件：它解释了为什么子任务做不成某件事。

为什么不允许子级请求审批：

- **技术原因**：子级运行在父级的工具执行内部，派发已经开始。若允许挂起，续跑时整个子循环会从头重来，已花的模型调用重复发生，有副作用的工具重复执行。"落盘挂起"要求抛出前无外部副作用，这对子级同样不成立。
- **安全原因（审批洗白）**：父级被拦下、被用户拒绝的操作，可以被重新包装成"子任务需要该权限"的审批卡片，用户看到的是一个正常的子任务请求，而不是自己刚拒绝过的动作。

被否决的折中是在派发时让主 Agent 一次性申请"子智能体的最高可用级别"，让用户批准整个能力包。这是用 N 次模糊授权换一次清晰授权：判断"这个子智能体可以联网"远比判断"这条命令该不该跑"困难。

子级也**不参考会话白名单**：它只做权限判定，不查"总是允许"。

### 4.2 死循环防护

子级复用工具包装层的重复指纹拦截与 `max_consecutive_blocks`（[工具执行](../02_runtime/06_tool_execution.md)）：连续被拦截达到上限抛 `LoopAborted`，子级以失败报告收场，不拖死父任务。

## 5. 报告与引用纪律

子智能体的最后一步输出一个 JSON，经 `build_report` 净化后变成 `SubagentReport`：

```python
SubagentReport(
    status:   "success" | "partial" | "failed",
    findings: list[SubagentFinding],   # statement, citations[], verified, dropped_citations
    unresolved: list[str],
    warnings:   list[str],
    steps_used, tool_calls, total_tokens, elapsed_sec, truncated,
)
```

### 5.1 引用白名单

每条结论要携带 `Citation(kind: file|artifact|url, ref, note)`。系统校验 `ref` 是否在子智能体**本次实际访问过**的资源集合里：

- URL 必须**精确命中**。
- 文件与产物允许**路径分量后缀双向匹配**，因为子智能体引用的路径形态常与工具入参不同（绝对与相对）；仍要求引用真实存在于访问记录中，伪造路径依旧被拦住。
- 引用整条丢弃的结论，`verified` 置为 `False`，渲染时标注"未经验证"。`verified` 由代码置位，模型无法声称。

访问集合只采集**资源型字段**：入参里的 `path`、`file_path`、`filepath`、`artifact_id`、`url`，结果元数据里的 `url`、`urls`、`artifact_id`、`artifact_path`、`source_url`，以及产物路径及其文件名。**刻意不采集检索词**，否则子智能体可以把关键词当作引用，白名单就失效了。

### 5.2 归一化

状态由代码归一：没有任何结论的归为 `failed`；存在未解决问题的 `success` 降为 `partial`。条数与长度受 `max_findings`（6）、`max_answer_chars`（400）、`max_citations`（8）约束。

### 5.3 回流时的信任级

`spawn_subagent` 的类属性声明 `trusted`（接口可信：输出经固定模板渲染并过引用白名单），但**每次返回时在结果上覆盖为 `untrusted`**：回流内容是受限子智能体的总结，可能失真，需要主 Agent 交叉核对。这正是工具层允许调用期信任级覆盖的原因。

`ok` 的语义：**只要拿到了结构良好的报告就算成功**。子智能体如实报告"无法完成"是有效结论，不应计入主循环的连续错误；只有"根本没跑起来"（授权被拒、内部异常）才是 `ok=False`。

## 6. 事件

| 事件 | 内容 |
|---|---|
| `subagent.started` | 角色、深度、授予的工具 |
| `subagent.step` | 步号与本步工具名 |
| `subagent.tool` | 工具名、是否成功、耗时、是否不可信、摘要（总线限长 300 字符） |
| `subagent.blocked` | 越级被拒：工具、所需级别与当前级别、动作类型、原因 |
| `subagent.finished` | 状态、步数、调用数、Token、结论数、已验证结论数、耗时 |

原始工具输出不进入事件流、不进入主状态、不进入检查点。

## 7. 配置

```toml
[subagent]
enabled = true
model_tier = "fast"
max_depth = 1                # 宽度替代深度
max_assigned_tools = 6
max_findings = 6
max_observation_chars = 4000 # 子级单条观察值，内存截断不落盘
max_answer_chars = 400
max_citations = 8
max_report_chars = 3000
denied_tools = ["spawn_subagent", "websearch"]
```

`enabled=false` 时主 Agent 没有动态委派能力。

## 8. 已发现的问题

| # | 问题 | 级别 | 建议 |
|---|---|---|---|
| 1 | **引用白名单把"失败的调用"也算作已访问。** 访问集合在每个被派发的调用后累加，不看 `result.ok`。子智能体读一个不存在的路径，调用失败，这个路径仍进入白名单，之后可以被当作"已验证"的引用 | 中 | 只在 `result.ok` 为真时登记资源；对 `view_file` 这类还可核对行号范围 |
| 2 | **子级内部的工具调用没有进入轨迹。** 运行器没有传入轨迹记录器，只发事件；协议里"违规会被审计记录"的承诺没有持久化支撑。事件流不落盘 | 中 | 向轨迹写入子级的每次调用、拒绝和结论，并标注 `parent_task_id` 与 `subagent_depth` |
| 3 | **子级没有金丝雀检查。** 泄露检测只在主执行阶段 | 中 | 统一在循环层对所有模型响应检测，见 [信任 §8](../05_security/03_trust_and_injection.md) |
| 4 | **子级与父级共享工具实例。** 例如 `BashTool` 内部的步号计数器，子级调用会推进它。目前无害，但共享可变状态是隐患 | 低 | 子级使用工具的受限视图，或要求工具实例无共享可变状态 |
| 5 | **子级观察值只按字符截断，不落盘。** 被截掉的部分子智能体取不回 | 低 | 与主上下文共用裁剪器与 `read_artifact`，见 [观察值治理 §6](../03_context/01_observation_governance.md) |

## 9. 不变量

1. 子级工具集是父级工具集的子集，且不含委派类工具。
2. 子级权限不高于父级，且全程不可升级。
3. 子级不能请求人工审批，越级即失败。
4. 授权在派发前一次性确定，进入后不可扩张。
5. 子级的中间观察值不进入主状态与检查点。
6. 回流的结论一律标记为不可信。
7. 子级的引用只能指向它实际访问过的资源。
8. 子级没有独立额度，也不能绕过父级的取消。

## 10. 测试要点

- 收窄：申请不在父表内的工具、申请 `spawn_subagent`、申请黑名单工具、工具条数超限，均整体拒绝；`assigned_tools` 为空拒绝。
- 深度：`max_depth=1` 时子级无法再派发。
- 权限：父级为 `read_only` 时，子级的写类调用被拒，且不挂起；`subagent.blocked` 事件被发出。
- 取消：取消父任务时子级随之取消，transcript 配对完整。
- 死循环：子级连续被拦截达上限，以失败报告收场。
- 引用：伪造路径被丢弃；失败调用的路径**不**进入白名单（修复后）；URL 精确匹配；后缀匹配的边界。
- 状态归一：无结论为 `failed`；有未解决问题的 `success` 降为 `partial`。
- 信任：返回结果总是 `untrusted`；`ok` 在拿到报告时为真。
- 并发：同批多个 `spawn_subagent` 互不干扰（各自独立 transcript）。

## 11. 待定

- 委派的成本收益提示是否应该由系统给出，而不仅写在工具描述里。例如在连续派发多次后提示"这些子任务可能不值得委派"。
- 子级是否允许使用只读的 `read_artifact`，以及它与父级共享哪些产物。
- 是否支持多个子智能体之间传递结论，目前只能经由父级中转。

## 12. 实现状态

代码在 `agent_runtime.subagents.delegate`（`report`、`render`、`runner`、`tool`），由 `RuntimeFactory` 在 `subagent.enabled` 时装配进主工具表。账本、`token_budget` 参数、`max_total_tokens` / `min_token_budget` / `max_spawns_per_task` 已删除；保留 `max_steps` 与 `max_wall_time_sec`（子级单次运行的步数与超时）。父工具表是派发时刻的快照，子工具表是它的子集（独立的 `ToolRegistry`，但工具实例仍与父级共享，§8 第 4 项未做）。

- **三道收窄**：工具集**全有或全无**（不存在、`spawn_subagent` 本身、`denied_tools`、超过 `max_assigned_tools`、空列表、非字符串都整体拒绝，失败信息列出当前可授权的工具）；权限取父任务基线、子级不可升级；深度 `当前 + 1 ≤ max_depth`。
- **越级即失败，绝不挂起**：每次调用用 `check_permission` 判定，越级的合成失败观察值（"你不能发起审批"）并发 `subagent.blocked`，也不参考会话白名单；不在分配表里的工具即使模型要求也只得到"没有工具"。
- **§8 第 1 项（失败调用进白名单）已修**：访问集合只在 `not result.failed` 时登记；检索词不是资源。文件引用做路径分量后缀双向匹配，但**只有文件名相同而目录各异不算**（写测试时发现裸文件名会蹭上任何同名路径）；产物句柄（不带扩展名的文件名）与 `artifact://` 前缀都认；URL 精确匹配。
- **第 2 项（轨迹）已修**：`subagent.*` 事件进入轨迹（类型 `subagent`）。**第 3 项（金丝雀）已修**：子级每个模型响应都检测，泄露即终止。**第 5 项未做**：子级观察值只按字符截断，不落盘。第 6 项（派发次数续跑后重置）随派发次数上限一并取消。
- **事件里没有原始输出**：`subagent.tool` 的 `summary` 只有成败与规模（`成功，120 字符`），失败时才带一小段原因；一个整套应用的测试断言子级读到的文件内容不出现在事件流里。
- **回流**：工具类属性 `trusted`，每次返回时覆盖为 `untrusted`；只要拿到结构良好的报告就 `ok=True`（子级如实报告"做不到"不计连续错误）；渲染不自带外层信封（信封由编排层统一加）。未经验证的结论明确标注，`verified` 由代码置位。
- **Token 额度与账本已取消**（[0006](../12_decisions/0006-pure-agent-loop.md)），代码里的 `BudgetLedger` / `ChildBudget` 已删除，换成只做统计和计时的 `ChildUsage`。**与设计的偏差：子级的 `max_steps` 与单次运行超时（`max_wall_time_sec`）仍保留**，因为子循环没有父循环的取消与重复拦截，需要一个兜底；这两项不是预算，不随用量变化。
