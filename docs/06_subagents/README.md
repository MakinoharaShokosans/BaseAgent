# 子智能体

子智能体是运行在**独立上下文**里的有界执行体。主 Agent 把子任务交给它，只收回一份结构化结论，中间产生的大量观察值不会进入主上下文。

BaseAgent 里有两种子智能体，目的不同，隔离方式也不同。

## 两种子智能体

| | websearch 工具 | 动态子智能体 |
|---|---|---|
| 入口工具 | `websearch` | `spawn_subagent` |
| 目的 | **安全**：隔离不可信的外部内容 | **效率**：隔离大量中间观察值 |
| 工具集 | 固定，只有 `web_search` | 每次由主 Agent 提议，经父表收窄 |
| 本地权限 | 无 | 不高于父级，且不能请求审批 |
| 回流形态 | `WebSearchReport`，代码模板渲染 | `SubagentReport`，引用白名单校验 |
| 回流信任级 | 报告自带 `untrusted` 信封 | 返回时覆盖为 `untrusted` |
| 能力是否可变 | 否 | 是，但只降不升 |

## 共同的设计要点

1. **中间内容不离开一次函数调用。** 子智能体用自己的消息列表，循环结束即丢弃；不写入 `AgentState`，不进检查点。
2. **回流的只有强类型报告。** 报告由代码模板渲染，不透传子模型原话；引用必须落在白名单内。
3. **没有独立额度。** 子智能体不设步数、Token、挂钟上限（[0006](../12_decisions/0006-pure-agent-loop.md)）；防止失控靠深度上限、重复指纹拦截与父任务的取消。
4. **失败不抛异常。** 任何阶段出问题都降级为带 `warnings` 的报告，绝不把异常或中间观察值透传给主 Agent。
5. **用量由框架读取，不信自述。** 事件里的用量统计取自模型响应，不取自子智能体的文本。

## 与权限、信任的关系

```mermaid
flowchart LR
    M[主 Agent] -- 提议 --> T[spawn_subagent]
    T -- 收窄 --> P[权限与工具集]
    T -- 运行 --> R[子智能体循环]
    R -- 报告 --> C[引用白名单 / 类型化契约]
    C -- untrusted 信封 --> M
```

- 权限收窄见 [权限分层 §7](../05_security/01_permission_tiers.md)。
- 回流内容的信任处理见 [信任与注入 §3](../05_security/03_trust_and_injection.md)。

## 代码探索场景的委派定位

在大型代码库中，针对需要大范围阅读但仅需回流关键结论的探索场景，适合使用 `spawn_subagent`：
- 为其授予只读工具（`view_file`、`grep`、`list_dir` 或受限 `bash`）；
- 在完全隔离的子上下文中并行搜索与阅读，最终仅将带有具体文件/行号引用的结构化报告回流给主上下文，有效保护主上下文空间。
