# 前端重设计

> **状态：前端主体已按本文实现；§9 的后端核心缺口（G1/G2/G4/G5/G6/G7/G10）已在后端就绪并打通，界面解除降级置灰状态。** 实现对照见 §13。
> §11 的决定已经敲定，视觉语言（色彩、字体、动效）沿用 [03_visual_design.md](03_visual_design.md)，审批与安全界面沿用 [02](02_approval_and_safety_ux.md)，本文不重复。

## 1. 为什么要重设计

现在的界面是逐步长出来的，能用，但有几处结构性的缺口：

| 问题 | 现状 |
|---|---|
| 会话没有名字 | `SessionOut` 只有 `session_id`、`workspace_id`、`created_at`，侧栏只能用时间或首条消息凑标题，无法重命名、置顶、搜索 |
| 没有流式 | 后端 LLM 网关是整条请求、整条响应；`model.reply` 在一轮结束后一次性到达。用户看着空白等几十秒 |
| 思考链被截断 | `model.reply.reasoning` 是截断的，且只在事件里；完整内容只在 `llm_calls` 里，前端没有展示 |
| 工具调用信息太少 | `tool.result.result` 只有前 500 字符；没有耗时、退出码、是否被截断；看不到"这条命令到底输出了什么" |
| 设置只有一小块 | 只能改会话模型、上下文上限、**一个**系统提示词；MCP 与技能只读；提示词的其他分区看不到 |
| 没有路由 | 刷新后回到默认视图，无法分享"某个会话"的链接，无法在设置页之间跳转 |
| 对象关系不清楚 | 工作区、会话、任务三层的关系没有在界面上讲清楚：记忆在哪一层？技能在哪一层生效？改了设置影响谁？ |

## 2. 设计原则

1. **前端是投影**（沿用 [01](01_architecture.md) §1）：事实在服务端，刷新后一切可恢复。因此**需要 URL 路由**，界面状态尽量放进地址。
2. **每个开关都说清楚"影响谁、何时生效"。** 后端的挂载规则（[0007](../12_decisions/0007-capability-mounting.md)）是"清单只在任务边界变化"，所以 MCP、技能、提示词的改动**下一个任务才生效**。界面必须显示这一点，而不是让用户以为立刻生效。
3. **作用域是一等公民。** 同一类设置可能在全局、工作区、会话三层出现，每处都标出作用域徽标，并显示"被谁覆盖"。
4. **详略分层。** 默认只显示一行摘要，点开才看全部；但"全部"必须真的能看到（完整命令、完整输出、完整思考、完整提示词），不能只截断。
5. **运行中的东西要能被打断。** 任何长任务都有取消；等待审批、失败、断线都是可见且可操作的状态，不是静默。
6. **不信任的内容照旧隔离。** 工具输出、网页、MCP 返回、思考内容一律按文本渲染，不执行；沿用 `SafeMarkdown`。
7. **界面文案克制。** 不写引导语、客套话、功能介绍；空状态只放一个图标和一个动作。说明性文字只出现在「有风险」或「必须知道」的地方（删除、信任、下个任务生效）。
8. **图标为主，提示悬停显示。** 操作按钮用 SVG 图标，不带文字；含义放在**自定义气泡**（hover / 键盘聚焦显示）里。气泡、下拉、菜单、弹窗统一走**层级令牌**与 Portal，不被父级的 `overflow` 或层叠上下文裁切。
9. **控件全部自绘。** 下拉框、滑动条、开关、复选框、数字步进、滚动条都不用浏览器原生样式。
10. **响应式。** 桌面三栏、平板两栏、手机单栏（侧栏与右侧栏都是抽屉，设置页逐级进入）。
11. **后端先行的部分明确标出来。** 本文 §9 列出所有需要后端配合的缺口，前端按"有就用、没有就降级"写，不阻塞。

## 3. 对象模型与信息架构

### 3.1 三层关系

```
工作区 Workspace ──< 会话 Session ──< 任务 Task（一次提交 = 一个任务）
   │                    │                  │
   │ root_path          │ 对话流水 turns    │ 计划、回合、工具调用、审批、产物
   │ 描述               │ 会话记忆（摘要/事实/失败）
   │ 工作区记忆          │ 会话设置（模型、上下文上限）
   │ 项目规则文件        │
   │ 工作区技能目录      │
```

| 层 | 是什么 | 生命周期 | 在界面上的含义 |
|---|---|---|---|
| 工作区 | 一个项目目录，**安全边界**：工具的 cwd、文件接口的根、沙箱的根 | 用户创建，删除会**级联删除**其下全部会话、记忆 | 侧栏的一级节点。决定"Agent 能碰哪些文件" |
| 会话 | 一段连续对话 | 用户新建，可分支（fork），可删除 | 侧栏的二级节点。对话历史与会话记忆属于它 |
| 任务 | 用户在会话里发出的一条消息触发的一次 Agent 运行 | 异步执行，有明确终态；同一时刻并发数受限（默认 1） | 对话流里的一个"运行块"。右侧卡片显示的是**当前任务** |

跨层的共享关系，需要在界面上一眼看懂：

| 东西 | 作用域 | 谁能看到 / 影响谁 |
|---|---|---|
| 工作区记忆（profile、guidelines、architecture、pitfalls） | 工作区 | 该工作区下**所有会话**的所有任务；会话结束时的"沉淀"可上浮到这里 |
| 会话记忆（摘要、事实、失败记录） | 会话 | 仅该会话；fork 时按分支点规则带走一部分 |
| 项目规则（`CLAUDE.md` / `AGENTS.md` / `.baseagent/rules.md`） | 工作区目录 | 该工作区；默认关闭（需 `allow_workspace`），检测到但未启用时要提示 |
| 技能 | 内置 / 全局 / 工作区三个来源 | 内置与全局对所有工作区；工作区来源仅该工作区，且**不可信**，默认拒绝 |
| MCP 服务器 | 全局（配置文件） | 所有工作区 |
| 系统提示词覆盖 | 全局 | 所有任务 |
| 模型、上下文上限 | 会话（缺省取工作区设置，再缺省取全局） | 该会话的后续任务 |
| 默认权限基线、默认模型、项目规则开关 | 工作区 | 该工作区下新建的会话与提交的任务；会话 / 任务可覆盖 |
| 权限基线 | 任务（提交时指定） | 单个任务；`full_permissions` 每次都要确认 |

### 3.2 全局导航

```
┌────────────┬───────────────────────────────────────────┬─────────────┐
│ 侧栏        │ 主区（路由决定）                            │ 右侧卡片     │
│ 工作区→会话  │  /w/:wid/s/:sid        对话                │ 任务         │
│            │  /w/:wid               工作区概览           │ 上下文       │
│ 底部：设置   │  /settings/...         设置页（全屏）       │ 产物         │
└────────────┴───────────────────────────────────────────┴─────────────┘
```

**路由**（需要引入轻量路由，如 `react-router` 或 `@tanstack/router`，决定见 §11）：

| 路径 | 内容 |
|---|---|
| `/` | 重定向到最近使用的会话；没有则显示空状态引导（新建工作区） |
| `/w/:wid` | 工作区概览（记忆、规则、技能来源、文件、会话列表） |
| `/w/:wid/s/:sid` | 对话；`?task=:tid` 定位到某个任务 |
| `/settings/models`、`/prompts`、`/skills`、`/mcp`、`/tools`、`/general` | 设置各页 |

刷新、后退、复制链接都能回到原位。最近一次的位置存 `localStorage` 仅作为 `/` 的默认去向。

## 4. 侧栏：工作区与会话

### 4.1 布局

```
┌──────────────────────────┐
│ 🔍 搜索会话…       ⌘K     │
│ ＋ 新会话                 │   ← 在当前工作区下新建
├──────────────────────────┤
│ ⚑ 需要你处理 (2)          │   ← 跨工作区的待办：等待审批 / 失败
│   ◐ 重构配置加载  BaseAgent│
│   ✕ 修复登录      web-app │
├──────────────────────────┤
│ ▾ BaseAgent          ⋯   │   ← 工作区：名称 + 更多
│   ● 重构配置加载   运行中  │   ← 会话：状态点 + 标题 + 相对时间
│   ○ 讨论文档结构   2 小时  │
│   ○ 修一个测试     昨天    │
│ ▸ web-app            ⋯   │
│ ▸ scratch            ⋯   │
│                          │
│ ＋ 添加工作区              │
├──────────────────────────┤
│ ⚙ 设置    ◐ 主题   ▭ 折叠  │
└──────────────────────────┘
```

### 4.2 状态与徽标

会话行的状态点由**该会话最近一个任务**决定，并随 SSE 更新（只订阅当前任务时，其他会话的状态靠轮询 `GET /sessions/{id}/tasks?limit=1`，或后端提供全局事件流，见 §9 G12）：

| 状态点 | 含义 |
|---|---|
| 实心脉动 | `running` |
| 黄色 | `waiting_for_approval`：**这是最需要用户注意的状态**，同时出现在顶部"需要你处理" |
| 红色 | `failed` / `terminated` |
| 灰色空心 | 空闲或已完成 |
| 蓝点 | 有未读的新结果（本地记录最后一次查看的 `seq`/时间） |

"需要你处理"区固定在最上面，只列等待审批与新近失败的会话，点击直达。折叠态的侧栏用图标列加红黄点提示。

### 4.3 管理操作

| 对象 | 操作 | 说明 | 后端 |
|---|---|---|---|
| 工作区 | 新建 | 弹窗：名称、目录（目录浏览器 / 原生选择器）、描述；路径被后端校验（必须存在、非根目录、不重复） | 已有 |
| 工作区 | 重命名 / 改描述 | 行内编辑 | 已有 `PATCH` |
| 工作区 | 删除 | **二次确认并展示将被删除的内容**：N 个会话、N 条记忆。要求输入工作区名确认。强调"不会删除磁盘上的项目文件" | 已有；计数需要新增或由前端拼 |
| 工作区 | 打开概览 | 进入 `/w/:wid` | — |
| 会话 | 新建 | 默认继承工作区；标题自动生成，可后改 | 已有；**标题字段缺**，见 G1 |
| 会话 | 重命名 | 双击或菜单 | **缺**，G1 |
| 会话 | 分支 Fork | 从最新或从某条消息处分支（消息上悬停出现"从此处分支"） | 已有 |
| 会话 | 置顶 / 归档 | 置顶的排在工作区内最前；归档的默认隐藏、可在过滤里看到 | **缺**，G1 |
| 会话 | 删除 | 确认；若有运行中的任务，先要求取消 | 已有 |
| 会话 | 移动到别的工作区 | **不做**：会话的记忆、工具 cwd 都绑定工作区，移动语义不清；用"分支到…"代替会改变安全边界，同样不做 | — |
| 搜索 | 按标题 / 首条消息搜索 | 先做客户端过滤（已加载的会话）；全文搜索看需求 | G13（可选） |

排序：工作区按最近活动；会话在工作区内：置顶 → 运行中 → 最近活动。

### 4.4 工作区概览页（`/w/:wid`）

侧栏只放导航，管理放在概览页，避免侧栏塞满：

```

/home/u/Projects/BaseAgent        描述：……  [编辑]

┌ 项目规则 ──────────────────────────────────────────────┐

└────────────────────────────────────────────────────────┘
┌ 工作区记忆 ───────── 4 个分区，共 12 条 ──────────────────┐
│ profile / guidelines / architecture / pitfalls          │
│ 每条：文本 · 来源 · [删除]            [＋ 手动添加事实]    │
└────────────────────────────────────────────────────────┘
```

## 5. 对话区

### 5.1 消息模型

不再把每个事件各画一行，而是把一次任务归并成**块（block）**，一个 `reducer` 产出有序的块列表：

```
任务运行块 RunBlock（对应一个 task）
├─ 用户消息            user
├─ 回合 Turn 1
│   ├─ 思考块          reasoning      可折叠，流式
│   ├─ 汇报文本        assistant text  流式；模型每一步的"已完成/下一步/进度"
│   └─ 工具调用卡片[]   tool           见 §5.4
├─ 计划变更标记         plan.updated   行内小条，点击高亮右侧任务卡
├─ 审批卡片            approval       内联，见 02
├─ 子智能体 / 联网搜索   subagent / websearch   折叠组，见 §5.6
├─ 压缩标记            context.compacted    分隔线："已将 N 步并入摘要"
├─ 回合 Turn 2 …
└─ 终态块              task.finished  交付结论（Markdown）+ 统计 + 操作（重跑 / 下载轨迹）
```

回合的分组依据是 `turn`（回合序号），**不是**事件条数（沿用 [01](01_architecture.md) §6）。

### 5.2 流式输出

**现状**：网关不是流式的（`openai` 客户端按整条响应读取），所以 `model.reply` 是一轮结束后才来的。要做流式必须后端配合，见 §9 G2。

**事件设计**（新增，向后兼容：旧客户端忽略未知事件）：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `model.delta` | `turn`、`kind: content \| reasoning`、`text` | 增量文本，合并到当前回合对应块 |
| `model.tool_call_delta`（可选） | `turn`、`index`、`name?`、`args_delta` | 工具参数边生成边显示，用于长命令 / 长文件内容。可降级为不做 |
| `model.reply`（保留） | 完整内容，权威 | 到达时**覆盖**流式累计的内容，作为最终一致的版本 |

要点：

- **权威版本以 `model.reply` 为准。** 流式只是预览；断线重连后缓冲里只有 `model.reply`，前端也能还原。
- 增量文本频率高，SSE 的 `seq` 不应为每个 delta 单独占一个持久化事件：delta 走"不持久化、可丢弃"的通道（类似心跳），丢了不影响最终结果。这是后端的设计点，见 G2。
- **脱敏**：金丝雀与密钥的脱敏在增量上更难（敏感串可能被切在两个 delta 之间）。后端对增量做滑动窗口检测；前端不做脱敏，也不假设 delta 已脱敏到可永久保存。
- 前端渲染：文本末尾带闪烁光标；Markdown 增量渲染时要容忍未闭合的代码块 / 列表（渲染前补全）；使用 `requestAnimationFrame` 批量合并 delta，避免每个 token 触发一次 React 渲染。
- 滚动：用户位于底部时自动跟随；一旦向上滚动则停止跟随并出现"回到最新 ↓"悬浮按钮。

**降级**：后端未提供 `model.delta` 时，界面显示"思考中…"的占位（带已耗时），`model.reply` 到达后整块出现。设计上不依赖流式才能工作。

### 5.3 思考链（reasoning）

| 方面 | 设计 |
|---|---|
| 位置 | 每个回合的最前面，一个可折叠块"思考" |
| 状态 | 流式中**展开**并显示旋转的"思考中 · 12s"；回合的汇报文本开始出现后**自动折叠**为一行"思考了 12 秒 · 1,240 推理 Token ›"，用户展开后记住本次偏好 |
| 内容 | 纯文本（等宽 / 次要色），**不当 Markdown 渲染**，不执行任何内容 |
| 完整性 | `model.reply.reasoning` 是截断的。展开时若被截断，显示"已截断 · 查看完整思考"，按需请求完整内容（`GET /tasks/{id}/llm_calls/{call_id}`，G3） |
| 安全 | 金丝雀由后端脱敏（[思考内容 §9](../07_llm_gateway/03_reasoning_content.md)）；前端把思考内容视为不可信文本 |
| 不返回思考的模型 | 不显示该块；若用量里有 `reasoning_tokens` 但没有明文，显示"模型已思考（内容不可见）· N Token" |
| 全局开关 | 设置 → 通用："默认展开思考 / 默认折叠 / 隐藏" |

### 5.4 工具调用卡片：能看到足够多信息

目标是用户**不用去翻日志**就能回答："它跑了什么、在哪跑的、花了多久、成功了吗、输出了什么、会不会改了我的文件"。

折叠态（一行）：

```
▸ bash   pytest tests/test_loop_kernel.py -x          ✓ 3.2s   exit 0     [workspace_write]
```

展开态：

```
┌ bash ─────────────────────────────────────── 回合 3 · 第 2 个调用 ┐
│ 命令   cd /home/u/Projects/BaseAgent/backend && pytest tests/…   [复制]│
│ 目录   /home/u/Projects/BaseAgent/backend                            │
│ 权限   workspace_write（命中规则：写工作区文件）                       │
│ 开始   14:03:07   耗时 3.2s   退出码 0                                │
├ 输出 ────────────────────────────────────────────────────────────────┤
│ stdout ▾  (等宽，ANSI 颜色转成样式，行号，可搜索)                       │
│ …………                                                                │
│ ⚠ 输出已截断：显示前 500 字符 / 共 18.4 KB   [加载完整输出] [下载]       │
│ stderr ▾  （有内容时才显示，红色边）                                    │
├ 影响 ────────────────────────────────────────────────────────────────┤
│ 写入 3 个文件：a.py · b.py · c.py        [查看 diff]                   │
│ 产物 artifact://abc  [打开]                                            │
├ 标记 ────────────────────────────────────────────────────────────────┤
│ 🛡 输出来自不可信来源（untrusted）  ·  已在上下文中折叠（可重读）        │
└──────────────────────────────────────────────────────────────────────┘
```

按工具类型使用不同的展开样式：

| 工具 | 展开内容 |
|---|---|
| `bash` | 命令（语法高亮）、cwd、环境限制摘要、stdout / stderr 分栏、退出码、耗时、超时 / 被杀死标记 |
| 文件读取 | 路径、行范围、内容（语法高亮、行号）、是否被截断 |
| 文件写入 / 编辑 | **统一 diff**（旧 / 新），新建 / 覆盖标记，文件路径可点击（高亮在文件树）；`base_hash` 冲突提示 |
| 搜索 / grep | 模式、范围、命中数、命中列表（可点击） |
| `websearch` | 主题、问题、轮次、来源数（见 §5.6） |
| `delegate`（子智能体） | 见 §5.6 |
| `load_skill` | 技能名、来源、信任、载入的正文（折叠） |
| MCP 工具 | `mcp__server__tool`，服务器、参数、返回；永远标 untrusted |
| 其他 | 参数 JSON（折叠）与结果文本 |

通用字段：工具名、参数（已脱敏，完整可展开）、`step`、开始时间、耗时、`ok`、权限级别与 `action_type`、`untrusted`、是否被上下文折叠、关联产物。

被拒绝 / 未执行的调用（审批拒绝、重复调用被拦、护栏拦截）用不同样式并显示原因，不与"失败"混淆。

**现有事件不够，后端要补**（G4）：

| 缺什么 | 补成 |
|---|---|
| `tool.result.result` 只有前 500 字符 | 保留摘要，**完整结果走产物**（`artifact_id`）；前端按需 `GET /tasks/{id}/artifacts/{aid}` |
| 没有耗时 | `duration_ms`、`started_at` |
| 没有退出码 / 超时 / 被截断标记 | `exit_code`、`timed_out`、`truncated`、`bytes` |
| 没有权限信息 | 已有 `action_type` 与级别，随事件带出 |
| 没有写入影响 | 文件类工具带 `changed_files[]`（路径 + 增删行数），diff 按需取 |
| 长命令实时输出 | `tool.output`（可选）：stdout / stderr 增量，与 `model.delta` 同样走不持久化通道 |
| 是否被上下文折叠 | 事件或快照里带 `folded` 标记（`context.fold`） |

### 5.5 执行过程中的状态与操作

| 状态 | 界面 |
|---|---|
| `queued` | 运行块顶部"排队中（并发上限）"，可取消 |
| `running` | 顶部细进度条 + 当前回合 / 步骤文字 + **取消**按钮；输入框仍可写，提交的消息**进入队列**（见下），不会并发提交 |
| `waiting_for_approval` | 审批卡片内联在流里、置于最新位置；标题栏和侧栏同时变黄；浏览器标签标题加前缀提示 |
| `failed` / `terminated` | 终态块显示 `termination_reason`、最后一个失败的工具调用、**重试 / 从检查点续跑**（`POST /tasks/{id}/resume`）、下载轨迹 |
| 断线 | 顶部横幅"事件流已断开，正在重连（第 3 次，8 秒后）"，带手动重连；序号缺口时自动同步快照后继续 |

**队列。** 任务运行或等待审批时提交的消息进入本会话的**排队区**（输入台上方的小列表），每条可**撤回**（移除）或**上移 / 下移**；当前任务到达终态后自动提交队首。规则：

- 队列只存在前端（`localStorage` 按会话保存），后端始终只看到一个一个顺序提交的任务，不引入服务端队列。
- 当前任务**失败 / 取消 / 终止**时队列**暂停**而不是自动继续（避免在出错的基础上继续堆任务），队列条显示暂停图标，用户点击继续或清空。
- 等待审批期间不自动提交。
- 页面刷新后队列保留；关闭页面期间不会自动提交（没有前端就没有调度者），再次打开时显示“队列已暂停”。

回合汇报文本沿用系统提示词要求的格式（"已完成 / 下一步 / 进度 N%"）：前端**不解析**它做业务判断，只作为文本展示；进度条的权威来源是计划（`plan.updated`）和回合数。

### 5.6 子智能体与联网搜索

折叠组，默认一行摘要，展开看明细：

```
▸ 子智能体  researcher  深度 1    8 步 · 14 次工具调用 · 已验证结论 3/5
```

### 5.7 输入台

沿用现有：模型下拉、权限选择（`full_permissions` 每次确认、不被记住）、"压缩记忆"。新增 / 调整：

- 草稿按会话保存在 `localStorage`（仅本机）。
- 显示当前上下文占比的小环（来自右侧上下文卡的同一份数据），接近高水位时变色，点击打开上下文卡。

### 5.8 历史与恢复

- 打开会话时，用 `GET /sessions/{id}/turns` 拉对话流水（用户 / 助手最终消息）；点击某条助手消息展开其对应任务的**完整过程**，数据来自 `GET /tasks/{id}/timeline`，必要时 `trace`。

## 7. 设置

### 7.1 结构

设置从弹窗升级为**全屏页面**（`/settings/*`），左侧二级导航：

```
设置
├─ 通用         主题、语言、思考默认展开、快捷键、访问令牌状态
├─ 模型         可用端点、档位（推理 / 快速）、降级顺序（只读）；会话默认模型
├─ 提示词       所有分区的查看与编辑（§7.3）
├─ 技能         Skills 管理（§7.4）
├─ MCP          MCP 服务器管理（§7.5）
├─ 工具         内置工具清单与 Schema（只读）
├─ 安全与权限   权限基线说明、信任来源、沙箱设置（只读）
└─ 诊断         健康检查、依赖状态、版本、导出日志入口
```

每个设置项统一带：**作用域徽标**（全局 / 工作区 / 会话）、**生效时机**（"下个任务"/"立即"）、**来源**（配置文件 / 界面覆盖 / 内置默认）和**恢复默认**。

"待生效"提示：当存在已保存但还没被任何任务采纳的改动时，设置页顶部出现条幅"3 项改动将在下个任务开始时生效"。若当前有任务在运行，明确说明"不影响正在运行的任务"。

### 7.2 通用与模型

- **模型页**：`GET /models` 的端点列表，按档位分组，显示 `context_window`、`max_output_tokens`、是否返回思考、是否本地端点；这里是**只读**的，因为端点与密钥在配置文件里（密钥永远不进浏览器）。"会话默认模型"在会话设置里改。
- **通用页**：主题、思考块默认状态、时间显示（相对 / 绝对）、是否显示 Token 统计、令牌状态（只显示"已通过同源代理注入"，不显示令牌值）。纯前端偏好存 `localStorage`。

### 7.3 提示词：查看所有分区，并能编辑

用户的两个诉求："看全"和"改得了"。需要先把"提示词"拆清楚，因为它们的性质不同：

| 类别 | 是什么 | 例子 | 可编辑？ |
|---|---|---|---|
| **A. 模板文件** | `prompts/*.md`，静态文本 | `system`（主 Agent 系统提示词）、`compactor`、`task_compactor`、`subagent`、`subagent_report`、`websearch_plan`、`websearch_extract` | 可覆盖（见下） |
| **B. 动态分区** | 每次请求由状态渲染出来 | 工具 Schema、技能清单、MCP 索引、项目规则、工作区记忆、会话记忆、任务数据、草稿区 | **只读**：内容来自别处，应去源头改 |
| **C. 固定安全指令** | 金丝雀指令、不可信内容信封说明等 | `CANARY_INSTRUCTION`、`wrap()` 的包装文案 | **不可编辑**，只展示并说明原因 |

页面结构（左列表 + 右详情）：

```
提示词
┌ 分区 ───────────────┬ system  ·  主 Agent 系统提示词 ─────────── ✎ 已自定义 ┐
│ 模板（可编辑）        │ 用途：每个任务的系统提示词段                          │
│  ● system   已自定义  │ 使用者：主 Agent      作用域：全局    生效：下个任务    │
│  ○ compactor         │ 长度：3,842 / 20,000 字符 · 约 2.1k Token             │
│  ○ task_compactor    │ ┌────────────────────────────────────────────────┐ │
│  ○ subagent          │ │ （等宽编辑器，行号，可搜索，占位符高亮）             │ │
│  ○ subagent_report   │ │ 你是 BaseAgent，一个在用户工作区内工作的……          │ │
│  ○ websearch_plan    │ └────────────────────────────────────────────────┘ │
│  ○ websearch_extract │ [编辑 | 对比默认 | 预览渲染]   [恢复默认] [保存]        │
│ 动态分区（只读）       │ ⚠ 编辑系统提示词不影响安全指令、工具说明与记忆渲染。     │
│  ○ 工具 Schema       │                                                    │
│  ○ 技能清单          │                                                    │
│  ○ MCP 索引          │                                                    │
│  ○ 项目规则          │                                                    │
│  ○ 工作区记忆        │                                                    │
│  ○ 会话记忆          │                                                    │
│  ○ 任务数据          │                                                    │
│ 固定（不可编辑）       │                                                    │
│  ○ 安全标记           │                                                    │
│  ○ 不可信内容信封      │                                                    │
├─────────────────────┴────────────────────────────────────────────────────┤
│ 〔查看某个会话的完整请求〕 选择会话 ▾  → 按真实顺序列出各段（含 Token），可展开全文 │
└──────────────────────────────────────────────────────────────────────────┘
```

**编辑体验**：

- 三个视图：编辑、与内置默认的**行级 diff**、预览（模板里若有占位符，用示例值渲染）。
- 保存前校验：非空（空白视同恢复默认，与现有规则一致）、长度上限、必需占位符是否仍在（后端声明）；明确提示"此段仅在下个任务生效"。
- **恢复初始**一键：所有模板（含 `compactor`、`task_compactor`、`subagent`、`subagent_report`、`websearch_plan`、`websearch_extract`）都以随发行版的**初始版本**为基线，改坏了可一键回到初始。不做版本历史，只保留“当前值 / 初始值”。
- 未保存离开时提示；保存成功后显示"已作为全局覆盖保存"。
- 覆盖存数据库覆盖层（§11），不做版本历史。

**"查看某会话完整请求"**：这是"能查看所有的提示词分区"的落点。以 `GET /sessions/{id}/context` 为骨架，按装配顺序列出每一段，显示 Token，展开显示该段的渲染全文（需要后端新增内容接口，G5）。按"越稳定越靠前、新内容只追加"的真实顺序展示，并标出缓存前缀边界（[提示词装配](../03_context/03_prompt_assembly.md)）。这页是排查"模型为什么这么做"的主要工具。

**安全约束**：

- 编辑权限属于本机用户；提示词覆盖不能关闭金丝雀 / 注入防护 / 权限闸门（它们不在可编辑集合内）。
- 展示动态分区时，金丝雀令牌必须被遮蔽（`describe()` 已不含金丝雀）；记忆里的不可信条目照旧带信任标记。
- 提示词文本是**数据**：预览渲染不使用 `dangerouslySetInnerHTML`。

| 工具级开关 | 逐个工具启用 / 禁用 |
| 暴露方式 | `pinned`（完整 Schema 常驻）/ `deferred`（只列索引，按需取回）；说明对上下文占用的影响 |
| 添加 / 编辑 | **不做**。服务器定义在配置文件里，界面只开关、查看、重连 |
| 信任说明 | 所有 MCP 返回一律 `untrusted`；开启一个服务器时展示它会运行的完整命令（不含环境变量值），需要确认 |
| 生效 | 开关 / 增删在**下个任务**生效；"重连"类操作立即作用于连接管理器 |
| 诊断 | 点击服务器可看握手信息、工具原始定义（消毒前 / 后对比）、被拒原因 |

**后端缺口**（G7）：只有 `GET /mcp/servers` 的状态；配置在 `config.toml`，**没有写接口**，也没有运行时覆盖层。覆盖层方案见 §11。

## 8. 前端实现要点

### 8.1 状态与数据流

```
URL（路由） ──┐
TanStack Query（快照类：工作区、会话、记忆、设置、技能、MCP、模型）
SSE（当前任务的事件） ──► reducer ──► 块列表（RunBlock[]）
useUiStore（仅界面偏好，localStorage）
```

- 保持 [01](01_architecture.md) 的结论：快照用请求，进度用事件；事件归约是**纯函数**（`reduceTaskEvent`），用事件序列回放测试。
- 重设计后 reducer 的产出从"行"改为"块"：`RunBlock → Turn → {reasoning, text, tools[]}`。流式 delta 合并进同一个块，`model.reply` 到达时覆盖。
- 全局任务状态（侧栏的状态点）：当前任务走 SSE；其他会话走低频轮询或后端的全局事件流（G12）。
- 设置类写操作用乐观更新 + 失败回滚；"待生效"状态由前端比较"已保存值"与"最近一个任务采纳的值"推出（需要后端在任务快照里回报采纳的值，或由后端直接给 `pending_changes`，见 G8）。

### 8.2 目录

```
src/
├─ app/            路由、布局、全局提供者
├─ api/            http、sse、endpoints（按资源分文件）、query keys
├─ features/
│   ├─ sidebar/        工作区树、会话行、待办区、搜索
│   ├─ workspace/      概览页、记忆、规则、技能来源
│   ├─ conversation/   消息列表、块渲染、输入台、滚动控制
│   │   ├─ blocks/     Reasoning、Text、ToolCall(+各工具渲染器)、Approval、Subagent、Websearch、Compaction、Final
│   │   └─ stream/     reducer、delta 合并、增量 Markdown
│   ├─ inspector/      任务卡、上下文卡、产物卡
│   └─ settings/       models、prompts、skills、mcp、tools、general、diagnostics
├─ components/     通用 UI（Select、Slider、Toggle、Diff、CodeView、Terminal 输出…）
└─ stores/、types/、utils/
```

工具调用的渲染器做成**注册表**（`toolName → Renderer`），新增工具时只加一个渲染器，缺省回退到通用"参数 + 结果"卡。

### 8.3 需要新增的通用组件

`Toggle`（带"下个任务生效"提示）、`ScopeBadge`、`Diff`（行级）、`CodeView`（语法高亮 + 行号 + 搜索）、`AnsiText`（终端输出）、`Collapsible`（带记忆）、`VirtualList`、`ConfirmByTyping`（删除工作区）、`PendingBanner`。

### 8.4 性能与可访问性

- 流式时 delta 合并到 `requestAnimationFrame`，每帧最多渲染一次；长输出 / 长 diff 虚拟化或分段懒渲染。
- 键盘可达：侧栏树遵循 `tree` 角色；卡片可折叠项用 `button` 与 `aria-expanded`；审批卡片的焦点管理沿用 02。
- `prefers-reduced-motion` 已通过 `MotionConfig` 处理，流式光标在该模式下不闪烁。

### 8.5 测试

- reducer：事件序列回放（含 delta 乱序 / 丢失 / `model.reply` 覆盖、断线重连后的重建）。
- 块渲染：各工具渲染器的快照与交互；截断 / 加载完整输出的流程。
- 设置：提示词编辑（保存、恢复默认、diff、长度上限）、技能 / MCP 开关与"待生效"提示。
- 路由：深链接、刷新恢复、不存在的会话。
- 安全：思考 / 工具输出 / 提示词预览中的 `<script>`、`javascript:` 不被执行。

## 12. 新增接口约定（前端按此调用，后端实现）

前端对下表中尚不存在的接口做**降级**：请求 404 / 405 时对应控件置灰，提示“后端未提供”，不影响其余功能。

| 接口 | 请求 / 响应要点 |
|---|---|
| `PATCH /sessions/{id}` | `{title?, pinned?, archived?}` → `SessionOut`（含新增的 `title`、`pinned`、`archived`、`updated_at`） |
| `POST /sessions/{id}/title` | 触发按首轮对话生成标题，返回 `SessionOut`（由前端在首个任务成功后调用一次） |
| `GET /workspaces/{id}/settings` / `PUT` | `{permission_level, model, rules_enabled}`，值为 `null` 表示沿用上层；附 `defaults` |
| `GET /prompts` | `[{name, kind: "template", title, usage, size, customized, max_chars}]`；动态分区与固定指令另有 `kind` |
| `GET /prompts/{name}` | `{name, content, default, customized, max_chars}` |
| `PUT /prompts/{name}` | `{content}`；`DELETE /prompts/{name}` 恢复初始 |
| `GET /sessions/{id}/context/segments/{seg}` | `{id, text, tokens}`（渲染全文，不含金丝雀） |
| `GET /skills` | 在现有字段上增加 `enabled`；`GET /skills/sources` → `[{source, enabled, count, trusted}]` |
| `PUT /skills/{name}/enabled` | `{enabled}`；`PUT /skills/sources/{source}` `{enabled}` |
| `GET /mcp/servers` | 在现有字段上增加 `enabled`、`exposure`、`command_preview`；`GET /mcp/settings` → `{enabled}` |
| `PUT /mcp/servers/{name}` | `{enabled?, exposure?, disabled_tools?}`；`PUT /mcp/settings` `{enabled}`；`POST /mcp/servers/{name}/reconnect` |
| `GET /workspaces/{id}/files/tree` | 已有；概览页只读使用 |
| SSE `model.delta` | `{turn, kind: "content"|"reasoning", text}`，不持久化 |
| `tool.result` 增加 | `duration_ms`、`exit_code`、`truncated`、`bytes`、`changed_files` |
| `tool.output`（可选） | `{step, stream: "stdout"|"stderr", text}`，不持久化 |

### 13.3 实现取舍

- **产物不单独占一张卡**：右栏宽度有限，产物列表并入任务卡，点击打开全文并可复制 / 下载。
- **上下文分段点击打开弹窗**：不强制跳到设置页，少一次导航；弹窗里仍是该段渲染全文。
- **MCP 放在设置**：右栏不再保留 MCP 卡；对话与工作区顶栏只放“在线数”入口。
- **滚动条不再隐藏**：全局 6px 细滚动条，长输出、侧栏、检视器都能看出还有内容。
- **禁用控件不用原生 `disabled`**：改用 `aria-disabled` + 事件拦截，悬停气泡和键盘焦点仍然有效。
- **已补齐交互亮点**：计划项点击平滑滚动至对应回合；提示词代码编辑器（独立行号槽、字符与估算 Token 指标、快捷键 Ctrl+F 搜索与匹配导航）；技能与 MCP 列表实时搜索过滤。
