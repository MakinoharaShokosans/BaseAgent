# 上下文继承

一次对话里产生的东西，不该全部跟着走：既不该一直留在后续每次模型调用里，也不该沉淀进会话记忆。读过的文件、跑过的命令输出，读多少存多少，迟早撑爆窗口。本文规定**什么继承、什么不继承、不继承时留下什么**。

## 1. 判断标准

对任何一条进入 transcript 的内容，依次问三个问题：

1. **能否用一次调用重新得到，且代价低于一路携带它？** 能，就不继承原文。携带成本是"Token × 之后所有模型调用次数"。
2. **会不会过期？** 会，就不继承。过期的内容比没有更糟，模型会照着旧内容推理。
3. **是结论或决定，还是原料？** 原料不继承，结论和指向原料的指针继承。

不继承时留下**存根**：足以让模型知道"这里有过什么、怎么再拿到"的一行确定性文本。

## 2. 两个层次

| 层次 | 对象 | 手段 | 原文 |
|---|---|---|---|
| **任务内** | transcript → 每次请求的视图 | 折叠成存根（[窗口与压缩 §3](02_window_and_compaction.md)） | 留在状态与检查点里，不改写 |
| **任务到会话** | 任务结束时往会话记忆里写什么 | 只沉淀结论与指针（[记忆 §5](04_memory.md)） | 不写入，轨迹文件可查 |

## 3. 任务内：不继承什么

| 类别 | 例子 | 存根保留 | 取回方式 |
|---|---|---|---|
| 文件读取 | `view_file` | 路径、行范围、行数 | 重放同一调用 |
| 目录与搜索结果 | `list_dir`、`grep`、`glob` | 调用、命中数 | 重放同一调用 |
| 命令输出 | `bash`：构建、测试、日志 | 命令、退出码、行数；失败时保留首个错误行 | 产物句柄 + `read_artifact` |
| MCP 返回 | 查询结果、接口响应 | 调用、规模；被裁剪的带句柄 | 幂等工具重放；其余靠句柄 |
| 重复调用的旧结果 | 同一只读调用重复多次 | 与较新一次相同或已被取代 | 最新一次保留原文 |
| 过期读取 | 读完后又被 `write_file` / `edit_file` 改过的文件 | 路径、"已过期：之后在第 N 步被修改" | 重新读取 |
| 失败尝试的细节 | 堆栈、完整报错 | 一行失败摘要，进笔记 | 无，需要时重跑 |
| 历史回合的思考内容 | `reasoning` | 不进存根、不进沉淀 | 回传规则见 [思考内容](../07_llm_gateway/03_reasoning_content.md) |
| 子智能体的内部过程 | 它读了什么、试了什么 | 无 | 只收它的报告，过程不进主 transcript |
| 被取代的计划与笔记 | 旧版 `update_plan` | 无 | 草稿回显只展示最新 |
| 网页原文 | 联网研究 | 无 | 只经隔离的websearch 工具，主 transcript 里只有提炼后的结论与来源 |

**可重放的存根不需要产物句柄。** 只读且幂等的工具（`view_file`、`list_dir`、`grep`、`read_artifact`），重新调用即可重得，存根里写明调用即可。不可重放的输出（命令、有副作用的 MCP 工具）必须带产物句柄，没有句柄的**不折叠**，否则永远取不回。

**过期是纯函数。** 一次读取是否过期，只看 transcript 里它之后是否出现过对同一路径的 `write_file` / `edit_file` 调用。过期的读取**不论多近**都折成存根，仅同一步内除外。通过 `bash` 修改文件无法识别，这是已知局限，见 §7。

## 4. 任务内：不折叠什么

- 用户消息与任务目标。
- assistant 的文字回复。
- 草稿回显（计划、笔记、证据提醒），它们在请求尾部，不在 transcript 里。
- 最近 `task_fold_keep_recent_steps` 步（默认 3）的工具往返，过期读取除外。
- 豁免工具的结果（默认 `load_skill`，技能正文截断会让流程指引残缺）。
- 存根并不比原文短的内容。

## 5. 存根的规则

- **确定性**：只由工具名、调用摘要、行数、字符数、退出码、句柄、过期标记决定，不含时间戳，同一内容多次折叠结果相同。
- **成批低频**：达到触发线才折叠，一次折到低水位，见 [窗口与压缩 §3.2.1](02_window_and_compaction.md)。
- **配对不破**：只改 tool 消息的正文，assistant 的 `tool_calls` 与其结果照常成对。
- **格式**：

  ```
  [已折叠] view_file: src/parse.py:1-240（240 行）→ 如需查看请重新调用
  [已折叠] view_file: src/parse.py（已过期：第 14 步被 edit_file 修改）→ 请重新读取
  [已折叠] bash: pytest -x（退出码 1，共 842 行；首个错误：AssertionError …）→ 完整输出见 artifact://obs_step_4_bash
  ```

## 6. 任务到会话：继承什么

任务结束，写进会话记忆的只有：

| 继承 | 来源 |
|---|---|
| 用户目标、纠正与偏好 | 会话流水（用户消息） |
| 交付结论与做出的决定 | 会话流水（assistant 最终回复） |
| 本任务确认的事实 | `facts` 笔记，过长度、注入扫描与去重 |
| 失败的做法与原因 | `failed_attempts` 笔记 |
| 改动过的文件与符号（指针） | `last_action_target` |
| 遗留问题 | 交付文本里的说明 |

**不继承**：整个工具往返（会话流水本来就只存问答）、所有观察值、思考内容、计划、子智能体过程、技能正文、存根。

原则是**引用优于内容**：记"改了 `parse.py` 的 `parse_header`"，不记那段代码。

## 7. 已知局限

- 通过 `bash` 修改文件（`sed -i`、重定向）不会让之前的读取被识别为过期。缓解：存根里的"重新调用"提示，加上编辑工具要求精确匹配旧文本，匹配失败时模型会重读。
- 过期判定只看路径，不看行范围：改动文件的另一部分也会让整个读取过期。偏保守，代价是多一次重读。
- 折叠触发依据装配器的分词估算，与服务商真实用量不严格一致，只做局部决策。

## 8. 不变量

1. 存根确定，折叠单调（折叠过的永远折叠）。
2. 折叠不改写 `state.messages`。
3. 没有取回途径的观察值不折叠。
4. 过期读取不以原文进入请求（同一步内除外）。
5. 沉淀不含任何观察值原文与思考内容。

## 9. 测试要点

- 可重放工具折叠后存根无句柄但带调用；不可重放工具无句柄时不折叠。
- 读 → 改 → 折叠：该读取变存根并标过期，即使在最近 K 步内；同一步内的读写不受影响。
- 同一只读调用重复：较旧的结果成存根，最新一次保留原文。
- 失败命令存根保留首个错误行。
- 沉淀结果不含观察值与思考内容。
- 折叠前后检查点内容一致；折叠重放确定。
