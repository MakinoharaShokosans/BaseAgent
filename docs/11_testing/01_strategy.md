# 测试策略

## 1. 现状

| 项 | 现状 |
|---|---|
| Agent 后端 | 约 48 个测试文件、231 个用例，pytest + pytest-asyncio |
| RAG | 约 61 个用例（随 RAG 删除） |
| 前端 | 16 个测试文件，Vitest + Testing Library |
| 工具 | `Hypothesis` 用于权限分类的模糊测试；`MockLLMGateway` 在 `conftest` 里 |
| 真实模型 | `tests/real_llm/`，带 `real_llm` marker，默认不运行，无密钥自动跳过，并强制把存储隔离到临时目录、限制步数与 Token |
| 缺口 | 多处测试直接依赖 LangGraph 与 LangChain 的类型；对抗性测试集中在权限分类，其他安全点覆盖不均；没有评测的统一报告格式 |

好的部分要保留：**默认全部离线、可重复**；真实模型测试显式触发并带成本保护；存储一律隔离到 `tmp_path`。

## 2. 分层

```
        ┌──────────────┐
        │ 评测（真实模型）│   少量，手动触发，统计型
        ├──────────────┤
        │  端到端 E2E   │   少量，真实进程，假模型
        ├──────────────┤
        │   集成测试    │   中等，多个真实模块，假外部依赖
        ├──────────────┤
        │   单元测试    │   大量，纯函数与单个类，毫秒级
        └──────────────┘
        ╲  贯穿各层：安全对抗、属性测试、契约测试  ╱
```

| 层 | 目标 | 速度 | 外部依赖 |
|---|---|---|---|
| 单元 | 一个函数或一个类的行为与边界 | 毫秒 | 无 |
| 集成 | 若干真实模块协作：主循环加检查点加工具；网关加熔断；API 加注册表 | 秒 | 假模型、假 sidecar、临时 SQLite |
| E2E | 真实进程：API、sidecar、前端接口 | 十秒级 | 假模型（脚本化），真实的 HTTP 与 SQLite |
| 评测 | 真实模型在代表性任务上的质量与稳定性 | 分钟级，花钱 | 真实端点，需密钥 |
| 安全对抗 | 对策略与边界的主动攻击 | 秒 | 视场景 |

## 3. 原则

1. **默认离线。** 不带 `-m real_llm` 就不得访问网络、不得使用真实密钥。任何测试意外访问外网视为缺陷。
2. **确定性。** 时间、随机数、UUID 都可注入；不依赖墙钟、不依赖执行顺序、不依赖其他测试遗留的状态。
3. **隔离。** 所有存储、产物、日志路径指向 `tmp_path`。测试之间不共享文件系统状态，不污染仓库。
4. **先写失败的回归测试再修缺陷。** 本文档集中记录的每一个已发现问题，修复时必须带一个先失败后通过的测试。
5. **测契约不测实现。** 断言可观察行为（输出、状态变化、事件、落盘内容），不断言私有函数的调用次数。
6. **把"已知防不住"也写成测试。** 对抗用例里区分"已覆盖"与"已知未覆盖"，后者带标记（如 `xfail(strict=True)` 加原因），防止日后误以为已经防住，也在被修复时提醒移除标记。
7. **失败信息要能直接定位。** 断言附带上下文，避免出现只有 `False is not True` 的失败。

## 4. 测试替身

### 4.1 假模型网关

脚本化的网关：按预设序列返回响应，记录收到的每次请求。

```python
gateway = FakeGateway([
    reply(json=planner_plan(...)),                 # 规划
    reply(tool_calls=[call("bash", {"command": "ls"})]),
    reply(text="done"),
    error(LLMUnavailableError(...)),               # 可注入异常
    reply(usage=None),                             # 无用量，测估算
    reply(reasoning="…", reasoning_state={...}),   # 带思考内容
])
```

要求：

- 能断言收到的请求：档位、消息序列、工具 Schema、`purpose`、是否传了 `response_schema`。
- 支持按调用序号或按 `purpose` 匹配响应，避免顺序脆弱。
- 响应用完后默认抛出明确的"脚本耗尽"错误，而不是静默返回空，防止测试悄悄通过。现状默认返回空 JSON，是个隐患。

### 4.2 假的外部服务

| 替身 | 用途 | 实现 |
|---|---|---|
| 假 `bash_shell` | 工具层与权限测试 | 内存里的 ASGI 应用，按命令返回预设结果，可模拟 403、422、排队、超时 |
| 假 `web_search` | 研究隔离区 | 返回预设搜索命中与页面，包含带注入内容的页面 |
| 假 MCP 服务器 | MCP 管理器 | 进程内的最小 MCP 服务，可模拟握手失败、畸形 Schema、恶意描述、调用超时、中途崩溃 |
| 假时钟 | 熔断、退避、截止时间、挂钟预算 | 可手动推进的时间源 |
| 假 LLM 服务端 | 网关的 HTTP 层 | 本地 HTTP 服务，可返回 429、5xx、慢响应、畸形体、不带 `usage` 的响应 |

### 4.3 构造器

提供测试数据构造器，避免每个测试手写几十行状态：

```python
state = make_state(goal="…", milestones=[…], messages=[user("…"), assistant(tool_calls=[…])], total_tokens=1000)
cfg = make_config(tmp_path, max_steps=5, permissions=…)
```

## 5. 各层要点

### 5.1 单元

- **纯函数优先**：路由、更新应用、权限判定、预算判定、循环检测、脱敏、注入扫描、编解码、Schema 转换、信封渲染。
- **属性测试**：用 `Hypothesis` 覆盖有不变量的函数。例如 `apply_update` 对 `messages` 只追加；`required_level_for` 对任意输入不抛异常且返回合法级别；编解码往返相等；脱敏后不含原始密钥；切片算法总是在 assistant 边界；账本守恒式。
- 不要在单元测试里起事件循环之外的东西。

### 5.2 集成

关键的集成场景：

| 场景 | 内容 |
|---|---|
| 主循环完整任务 | 假模型脚本驱动一次"规划、执行工具、评估、交付"，断言状态、检查点、事件、轨迹 |
| 预算熔断 | 步数、Token、挂钟分别触发，断言终止原因与可续跑 |
| 审批往返 | 挂起、重启（新建所有任务级对象）、带决策续跑；批准、拒绝、总是允许 |
| 崩溃恢复 | 在每个阶段边界与阶段中间"杀掉"循环（抛出特殊异常），重新加载检查点续跑，断言结果与不崩溃一致；派发中途崩溃时的"结果未知"处理 |
| 网关弹性 | 假 LLM 服务端驱动重试、降级、熔断、截止时间 |
| 子智能体 | 授权收窄、越级即失败、预算对账、引用白名单 |
| 研究隔离 | 带注入页面的假 `web_search`，断言主上下文里没有页面原文 |
| API 与注册表 | 提交、并发上限、审批、续跑、取消、SSE 重放与重连 |
| 记忆 | 任务结束沉淀、水位线压缩、级联删除 |

### 5.3 端到端

起真实的 API 进程与假 sidecar（或真实 sidecar），用 HTTP 与 SSE 从外部驱动，覆盖：提交、订阅、审批、续跑、取消、重启后恢复。前端的 E2E 用 Playwright 驱动关键路径（审批、断线重连、错误展示），但数量控制在个位数。

### 5.4 安全对抗

按 [安全](../05_security/) 的每份文档组织，见 [02_test_matrix](02_test_matrix.md)。

### 5.5 评测

用真实模型运行一组代表性任务，**统计**而不是断言：

| 指标 | 含义 |
|---|---|
| 任务成功率 | 验收通过的比例，按任务类别分组 |
| 步数与 Token 分布 | 中位数、P90，与预算的关系 |
| 格式失败率 | 各结构化场景的降级比例 |
| 重试与降级率 | 网关层 |
| 工具失败率与被拒率 | |
| 死循环与熔断命中次数 | |
| 注入对抗成功率 | 红队语料下，危险动作被执行的比例，应为 0 |

评测结果输出为统一格式的报告（Markdown 加 JSON），可跨版本对比。评测永远默认跳过，需要显式触发，并带预算保护：单用例步数与 Token 的硬上限、总预算上限。

## 6. 约定

| 项 | 约定 |
|---|---|
| 命名 | `test_<行为>_<条件>_<预期>`，如 `test_reserve_when_balance_below_min_is_rejected` |
| 目录 | 与被测模块的目录结构镜像 |
| 标记 | `unit` / `integration` / `e2e` / `security` / `real_llm` / `slow`；默认运行除 `real_llm` 与 `slow` 之外的全部 |
| 异步 | `asyncio_mode = "auto"` |
| 夹具作用域 | 默认函数级；昂贵的（起进程）用会话级并保证清理 |
| 覆盖率 | 目标：核心包（`core`、`loop`、`checkpoint`、`approval`、`guardrails`、`llm`）行覆盖 ≥ 90%，分支覆盖 ≥ 80%；其余 ≥ 75%。覆盖率是下限信号，不是目标 |
| 速度 | 单元与集成合计 < 3 分钟；超过则拆分或标记 `slow` |
| 依赖方向 | 用 `import-linter` 在测试里强制，见 [代码结构 §1](../01_architecture/03_code_layout_and_roadmap.md) |
| CI | 每次提交：lint、类型检查、单元、集成、依赖方向；每日：E2E、慢测试；手动：评测 |

## 7. 不变量

1. 默认测试集不访问网络、不使用真实密钥、不写仓库内的文件。
2. 每个已发现的缺陷有一个回归测试。
3. 测试之间互不依赖，可以随机顺序或并行运行。
4. 假模型脚本耗尽时报错，不静默通过。
5. 已知未覆盖的攻击以严格 `xfail` 标记在案。
6. 评测不进入默认运行。
