## 核心做法

1. **默认离线，确定，隔离。** 不访问网络，不使用真实密钥，存储指向临时目录；真实模型测试显式触发并带成本保护。
2. **每个已发现的缺陷先写失败的回归测试。** 系统发现的各类边界问题，都在 [测试矩阵 §10](02_test_matrix.md) 里有对应的测试名。
3. **把"已知防不住"写成严格 `xfail`**（目标；目前还没有这样的用例）。安全边界的局限用测试留案，被修复时提醒移除标记。
4. **黄金场景用脚本化的假模型驱动。** 关键场景（直接答复、工具往返、审批、拦截、恢复）都有断言型测试，位置见 [03](03_suite_and_evaluation.md) §2；固化轨迹文件逐项对照还没做。
5. **统计型评测与断言型测试分开。** 前者看分布与趋势，后者看对错。

## 优先级一览

- **P0**：安全与数据完整。子系统交付与合并的硬性门禁。
- **P1**：核心业务行为。
- **P2**：健壮性与边缘增强。

全部 P0 测试通过是任何功能合并的底线。
