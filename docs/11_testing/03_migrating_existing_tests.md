# 现有测试的迁移

改造不是从零开始。现有 230 多个后端用例和 16 个前端测试文件里，有相当一部分验证的是**业务行为**，换掉引擎之后依然有效。本文说明哪些保留、哪些改写、哪些删除，以及怎样用旧测试证明新实现与旧行为等价。

## 1. 分类原则

| 类别 | 判断 | 处理 |
|---|---|---|
| 行为测试 | 断言的是业务结果，与图引擎、消息库无关 | 保留，只改导入 |
| 类型耦合测试 | 行为有效，但用了 `langchain_core.messages` 的类型 | 在阶段 2 机械替换为自有消息类型 |
| 引擎耦合测试 | 直接构造 `StateGraph`、`MemorySaver`、`Command`，断言的是引擎的使用方式 | 重写，保留其验证的**意图** |
| RAG 测试 | 针对检索服务或其代理 | 删除 |
| 真实模型测试 | 默认跳过 | 保留，导入调整，之后纳入评测体系 |

## 3. 用旧测试证明等价

重写主循环最大的风险是遗漏 LangGraph 提供的隐含语义（并发更新合并、递归上限、重试、事件顺序）。对策是**行为等价性回放**：

1. 取旧版 `test_graph_workflow.py` 与节点测试里已经存在的假模型脚本和断言。
2. 在新循环上用同一份脚本驱动，**断言项保持不变**：
   - 每回合结束后的 `consecutive_errors`（阶段访问顺序与 `step_count` 随 0006 作废）；
   - 终止原因与最终状态；
   - 事件序列（名称与关键字段）；
   - 配对消息的完整性。
3. 任何差异必须逐个说明：是旧版缺陷（记录并修正），还是新版遗漏（修复）。不允许"测试改一改就过了"而不解释。

建议先在阶段 2 完成后、阶段 3 开始前，把这些脚本整理成独立的**黄金场景集**，放进 `tests/golden/`，用现有 LangGraph 实现跑一遍并**冻结其输出**（事件序列、状态快照）作为基线。新循环完成后对照基线。这样不依赖记忆去比较"旧版本来是什么行为"。

| 黄金场景 | 内容 |
|---|---|
| 直接答复 | 模型第一回合即给出最终回复，无工具调用 |
| 单工具往返 | 一次工具往返后给出最终回复 |
| 多步任务 | 多个回合，草稿计划被更新 |
| 连续失败 | 连续错误通知追加 |
| 死循环 | 指纹重复整批拦截 |
| 审批批准、拒绝、总是允许 | |
| 并发工具 | 一批多个调用，配对完整 |
| 子智能体 | 授予、越级被拒 |
| LLM 全部不可用 | 终止原因 |
| 金丝雀泄露 | 立即终止 |

## 5. 评测框架

现有 `src/evaluation/agent_bench`（轨迹指标与报告）保留并扩展，`rag_bench` 删除。

- 指标计算（成功率、步数分布、证据链合规率等）保留；证据句柄的正则里去掉 `rag://`。
- 扩展 [策略 §5.5](01_strategy.md) 列出的指标：格式失败率、重试与降级率、被拒率、红队成功率。
- 报告输出统一为 Markdown 加 JSON，带版本、模型、配置摘要，便于跨版本对比。
- `scripts/generate_test_reports.py` 里写死了 RAG 的测试统计与报告章节，需要重写：改为从 pytest 与评测的真实输出生成，不再用硬编码的数字模板。

## 6. 迁移步骤

按 [路线](../01_architecture/03_code_layout_and_roadmap.md) 的阶段对应：

| 阶段 | 测试动作 |
|---|---|
| 0 | 为每项低成本修复先写失败的回归测试；整理黄金场景集（在旧引擎上冻结基线） |
| 1 | 删除 RAG 测试与夹具；确认剩余测试全绿 |
| 2 | 机械替换消息类型；全绿后再进入下一阶段 |
| 3 | 重写引擎耦合的测试；用黄金场景回放新循环；崩溃恢复与审批集成测试 |
| 4 | 假 LLM 服务端、网关弹性、结构化输出、思考内容测试 |
| 5–7 | 对照 [测试矩阵](02_test_matrix.md) 补齐 |
| 8 | 评测框架与报告 |

## 7. 验收

- 阶段 2 结束时：旧测试集（去掉 RAG）全绿，只发生类型替换。
- 阶段 3 结束时：黄金场景在新循环上全部与基线等价，或有逐项说明的差异清单。
- 全部结束时：[测试矩阵](02_test_matrix.md) 的 P0 全部有对应测试且通过。

## 8. 待定

- 黄金基线是否纳入版本库长期保留，作为之后重构的回归防线。倾向保留，体积很小。
- 旧版 `documents/` 里的测试路线文档是否整体归档。它们描述的是旧引擎下的做法，新文档集以 `docs/11_testing` 为准。
