# 安全重构

重构 = 不改变外部行为的结构调整。没有测试保护的重构只是赌博。

## 步骤
1. **固定行为**：跑一遍现有测试并记下结果；覆盖不足的地方，先补特征测试（characterization tests）把当前行为钉住。
2. **找全影响面**：重命名或移动前，用 `grep` 找出所有引用（包括字符串里的名字、配置、文档、测试）。
3. **小步前进**：一次只做一种变换（重命名、提取函数、移动文件），每一步之后立刻跑相关测试。
4. **保持可回退**：每一步都应当单独成立。必要时用 `git --no-pager diff --stat` 看当前改动范围。
5. **最后统一收尾**：格式化、类型检查、完整测试，确认没有遗漏的引用。

## 注意
- 不要把重构和功能修改混在同一步：出问题时分不清是谁引起的。
- 公共接口（被外部使用的函数、命令行、配置键）改名需要兼容期或明确说明。
- 大规模机械替换优先用 `grep` 先看清范围，再逐文件 `edit_file`，不要用一条带通配的 `sed -i` 一把梭。
