# 修复缺陷

## 1. 复现
- 先拿到**可重复**的失败：运行出错的命令或测试，记下完整的错误信息与堆栈末尾。
- 复现不了就先别改代码：缩小条件（输入、环境、版本），或如实报告无法复现及已尝试的做法。

## 2. 定位
- 从堆栈最内层、属于本项目的那一帧开始读，不要从库内部开始。
- `grep` 找相关符号，`view_file` 读上下文；必要时 `git --no-pager log -p -n 3 -- <file>` 看近期改动。
- 形成一个**可证伪的假设**（「X 在 Y 为空时没判断」），再用一次最小的实验验证，而不是边猜边改。

## 3. 先写失败的测试
- 在现有测试的风格里加一个能复现该缺陷的最小用例，确认它现在**确实失败**，且失败原因就是这个缺陷。

## 4. 最小修复
- 只改必要的地方，不顺手重构、不改无关的格式。
- 用 `edit_file` 做局部替换，改完用 `view_file` 看一眼改动处。

## 5. 验证
- 先跑新增的测试，再跑相关模块的测试，最后跑完整的测试与静态检查（项目的 `make check`、`pytest`、`ruff`、`tsc` 等，以构建清单为准）。
- 只在**真的跑过并看到通过**之后才声称修好了；跑不了就说明跑不了的原因。

## 5. 交付
说明：原因（一句话）、改了哪些文件、新增了哪个测试、跑了哪些验证及其结果。
